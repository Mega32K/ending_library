# Render camera editing overlays inside the game frame

The central Game Frame Preview is also the spatial editing surface. Camera trajectories, view-space keyframe nodes, orientation markers, frustums, collaborator indicators, and Gizmo handles are rendered inside the current game scene using the same editor-local preview camera. Their visibility, depth, scale, occlusion, selection state, and hit testing are defined as part of the preview render rather than delegated to a separate director view or Picture-in-Picture panel.

The overlay layer must remain legible against the game scene through semantic colors, outlines, depth-aware styling, Stable World Overlay Scale, and non-color cues, while preserving the user's requested visual-first presentation. Local selection uses the Blockbench-inspired blue with shape or outline reinforcement; hovering a world node does not enlarge, glow, animate, or reveal controls. Ordinary overlays obey scene depth, while a locally selected hidden node or trajectory portion may retain only the restrained Occluded Selection Trace. The layer must follow the implicit selected-keyframe/playhead edit-target rule, keep target text and an explicit mode toggle out of the Gizmo area and Viewport Control Bar, submit continuous manipulation as one gesture transaction, and remain isolated from the actual gameplay camera and server runtime.
