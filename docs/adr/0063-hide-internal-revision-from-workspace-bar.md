# Keep internal revisions out of the project workspace bar

The responsive Project Workspace Bar keeps a visible Project Tab strip for opened projects, but the active tab uses the same surface color as the editor region below so the tab and workspace read as one fused Blockbench-like surface. The active tab remains identifiable through restrained shape, text, focus, and selection feedback rather than a raised contrasting panel. A Project Tab Draft Dot marks only the current player's local content-changing work that has not yet been accepted by the server; the bar does not display the internal project revision number as ordinary tab content.

The dot covers authored gesture previews that differ from their baseline, unconfirmed property or command drafts, Auto Key proposals, and submitted operations awaiting authoritative acknowledgement. Playback, playhead movement, selection, timeline zoom, viewport movement, workspace layout, and collaborative-preview state do not create it. Once an operation is accepted, any journal flush or snapshot delay is represented by Project Persistence Status in the Collaboration Status Area rather than by retaining the dot. Read-Only Inspection Tabs never show the dot.

A rejected operation clears the dot only when its local proposal is discarded or rolled back. If the interaction deliberately retains a correctable draft, such as a rejected new command event, the dot remains until that draft is accepted, cancelled, or otherwise discarded. Revision numbers remain part of the authoritative project and collaboration protocol and may still be shown in the Project Browser, dedicated review, history, recovery, publication, diagnostic, or bottom Editor Status Bar surfaces when that context requires them. This keeps primary navigation visually quiet without removing revision tracking, publication state, conflict detection, or server ordering.
