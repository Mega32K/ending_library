# Align collaborative preview joins to server logical time

An accepted `Explicit Collaborative Preview Join` is aligned through `Preview Logical Time Alignment`, not through the joining client's wall clock or the playhead value in an old request packet. The server response binds the participant to the current preview-session generation and Preview Revision Snapshot, then supplies the authoritative logical playhead, playback state, preview range, and a bounded time reference sufficient to project the current time when the response is applied.

When the shared preview is playing, the joiner starts at the current projected logical time and immediately follows the shared playback state. It does not render a slow visual catch-up, temporarily control playback, or send corrective seek operations. When the shared preview is paused, the joiner uses the exact authoritative paused time. Small local drift after admission may be corrected by bounded client-local evaluation or a server-authoritative sync update, but drift correction never changes project content, personal history, Preview Revision Snapshot, or the follower's control permissions.

If the preview-session generation, revision identity, lifecycle state, or alignment reference is stale or invalid before admission completes, the join is rejected as a whole and the client's Local Preview Snapshot remains active. Delayed or duplicate alignment packets are ignored after terminal cleanup. The alignment contract applies only to the editor's Collaborative Preview and never to gameplay-facing camera runtime or player input.
