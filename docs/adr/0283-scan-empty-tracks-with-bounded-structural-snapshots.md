# Scan empty tracks with bounded structural snapshots

Remove Empty Tracks uses an independent Bounded Empty-Track Scan for client preview and server confirmation. Each Project Tab keeps at most one latest-wins preview generation, while confirmation reconstructs and reclassifies the declared Empty-Track Cleanup Scope from the authoritative project baseline instead of trusting client candidate identities. Both paths may share the camera editor's finite background-work facility, but their task identity, immutable snapshot, cancellation generation, progress, and terminal state remain separate.

The structural snapshot contains only animation, Scalar Animation Track, and Additive Lane identities; keyframe counts; Lane type, name, and order flags; import and round-trip metadata; and active-reference protection flags. It never copies keyframe values, curves, a complete Project Document, players, worlds, screens, widgets, or other UI state. The scan proceeds through structure collection, empty-track classification, protection validation, and summary generation, publishing at most four progress updates per second.

One scan is limited to `100,000` instantiated Scalar Animation Tracks, `250,000` Additive Lanes, and an `8 MiB` structural snapshot. Client preview has a `5s` computation deadline; server confirmation has a `5s` queue-wait deadline and a `5s` scan deadline. Existing project and collaboration budgets apply before these maxima, administrators may lower but never raise the built-in limits, and integrated servers enforce the same policy as dedicated servers.

Cancellation, scope or lifecycle changes, stale baselines, timeout, and budget exhaustion release all retained scan state and produce no partial candidate list, automatic scope reduction, or automatic retry. Only a complete result from the current authoritative server generation may enter the atomic commit terminal gate; otherwise the project and personal Undo/Redo history remain unchanged.
