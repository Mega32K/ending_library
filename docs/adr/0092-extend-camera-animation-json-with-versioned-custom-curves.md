# Extend camera-animation JSON with versioned custom curves

The current per-channel camera-animation JSON evolves into Extended Camera Animation JSON. It retains every existing field and adds optional, explicitly versioned Curve Segment data capable of representing the same custom cubic Bézier curves used by the Project Document and runtime evaluator. Existing unversioned files and keyframes without curve data remain valid and retain their original `easing` behavior.

For an interval containing custom curve data, the new reader evaluates that curve as authoritative. The existing `easing` field remains present as the explicit Legacy Easing Fallback for older readers and deliberate Legacy Animation Format export. Converting an Easing Preset to a custom segment preserves that preset as the fallback; later control-handle edits do not modify it. A custom segment created without a source preset starts with `LINEAR`, and only an explicit inspector edit may replace the fallback. The editor never silently treats it as lossless when it differs from the authored curve: imports and exports display the active profile, both curve previews, and any downgrade consequence.

The extended JSON remains a per-channel animation document and does not gain a `modifierType` field. Modifier ownership is supplied by the selected track, explicit import mapping, or verified modifier-named directory. The JSON codec, packet transport, NBT or equivalent runtime persistence path, publication payload, resource reload path, and evaluator must all preserve matching curve semantics. Unsupported versions or malformed control data fail validation visibly rather than falling back silently.
