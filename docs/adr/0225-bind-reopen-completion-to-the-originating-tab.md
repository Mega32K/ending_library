# Bind reopen completion to the originating tab

A `Reopen Project` request follows the `Reopen Focus Handoff` rule. If its tab stops being the `Active Project Tab` before the request enters atomic commit, focus loss cancels the `Cancellable Reopen Request`. The archived tab keeps its held inspection document and returns to its current reopen-eligible state, while the newly focused project proceeds without a blocking prompt, forced wait, or queued background request.

If focus changes after atomic commit has begun, the request is allowed to reach exactly one terminal result. It never switches focus back or interrupts the project the player is now using. A successful result applies the freshly authorized Project Document and new empty personal history segment only to the original still-open tab. The tab returns to ordinary inactive project styling, clears the Archived Reopen Indicator, and shows the independent `Inactive Reopen Success Indicator`. Because that tab is inactive, its live collaboration portion immediately follows the inactive-tab contract: it retains no sustained Collaborator Presence, command-event lock, active editing lock, or live project subscription. A later focus performs the normal current-state revalidation before the tab joins live collaboration again.

A failed committed result records only the applicable `Reopen Failure Outcome` and bounded status marker on the originating tab. Closing that tab still invalidates its identity, so a later result cannot recreate it or attach to another tab. Tab switching remains available throughout the operation and never becomes a modal interaction.
