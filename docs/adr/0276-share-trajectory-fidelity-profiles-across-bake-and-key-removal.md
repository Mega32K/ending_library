# Share trajectory fidelity profiles across Bake and key removal

The unit-aware profile established for Bake in ADR-0271 becomes the shared Trajectory Fidelity Profile vocabulary for Bake and Remove Redundant Keyframes. Both tools expose High Precision (`0.1%` relative error, `0.001` block, `0.01°`), Balanced (`0.5%`, `0.005` block, `0.05°`), Draft (`2%`, `0.02` block, `0.25°`), and Custom with the same field-to-unit mapping. Each operation owns its selection independently: Bake remains Balanced by default, while redundant-key removal defaults to High Precision, and changing one tool never changes the other tool's current choice.

Every affected Additive Lane and its accumulated Scalar Animation Track must independently satisfy the applicable relative tolerance and actual-unit cap. Relative scale continues to use the source trajectory's real excursion and extrema, with numerically near-flat intervals judged by actual-unit error only. This keeps the meaning of a fidelity preset consistent across tools while preventing lane cancellation from hiding an unacceptable authored-layer error.

For the initial LINEAR-only removal defined by ADR-0275, the difference between the source and reconstructed trajectories is piecewise linear. Validation therefore evaluates the union of all affected source-key times and reconstructed interval endpoints to determine the exact maximum error for each affected Lane and accumulated Track; it does not use Bake validation probes or approximate sampling. A candidate whose resulting operation would exceed the selected profile remains protected, there is no `Remove Anyway` override, and the Tool Operation Preview reports proposed removals, protected candidates, maximum error, its time, and the applicable limits before authoritative recomputation.
