# Order same-time effect events explicitly

Command Animation Effect Events that share one authored timestamp remain independent stable-identity events and carry a server-maintained `executionOrder` within that timestamp. A newly created or newly retimed command event is appended after existing events at the destination time unless an explicit reorder operation says otherwise. The properties surface or context menu provides same-time move-earlier and move-later actions without introducing extra timeline hierarchy. Reordering is one validated collaboration revision and one personal Undo/Redo operation. Runtime scheduling sorts first by authored time and then by `executionOrder`; command events execute once in that order from the runtime target player. Import preserves a source array's stable order when available and otherwise derives one deterministic order from stable event identity.
