# Present the project browser as a responsive workspace tool tab

Opening the Camera Animation Editor without a requested project presents the Project Browser as the main workspace below the top menus and Project Workspace Bar. When a Project Tab is active, File > Browse or Open activates one temporary Project Browser Tool Tab instead of covering the editor with an unrelated modal or closing the project. The tool tab is not a Project Tab: activating it first applies the existing pending-operation and retained-draft safeguards, saves the previous Project Workspace Layout, leaves that project's Editing Session and Collaborator Presence, and keeps its tab open and inactive. Closing the browser or opening a project returns to a valid Project Tab and joins its current authoritative revision; if no project tab remains, the browser returns to its landing state.

The browser uses a Blockbench-inspired three-region layout. A fixed header provides search, sort, filters, New Project, and Import. A compact category rail exposes All, Owned, Editable, Recent, and Archived views. The central virtualized result list shows project name, owner, the current player's Owner or Editor role, last edit time, editor count, archive state, format compatibility, and internal revision. Selecting a result opens the Project Browser Detail Surface with full catalog metadata, membership summary, compatibility, and only the lifecycle actions valid for the current role and state. A double left click opens the selected project; right click opens its context-aware lifecycle menu. Result rows never reveal hover-only action strips.

Search, category, sorting, filtering, and scrolling are implemented as finite Project Catalog Queries with cursor pagination. New query input supersedes stale in-flight requests, scrolling prefetches only bounded neighboring pages, and the client retains a finite metadata cache rather than loading every project or Project Document in the world. Opening, renaming, duplicating, importing, archiving, restoring, or deleting still receives fresh server-side permission, revision, format, and destructive-operation validation. New-project and rename fields select their existing text automatically under the shared rename contract.

At narrow widths the category rail becomes a compact selector and the detail pane becomes a real drawer; list density, labels, and hit targets remain usable rather than scaling the complete interface down. Loading, no-results, no-permission, connection failure, server rejection, migration-required, and unsupported-newer-format cases use explicit Project Browser State Surfaces with meaningful recovery actions. While the Project Browser Tool Tab is active, the Editor Status Bar reports catalog connection, query, and failure state instead of presenting a stale active-project revision or collaboration summary. Browser navigation state is local to the connected editor lifecycle, never project content, and is released when its tool tab and connection lifecycle end.
