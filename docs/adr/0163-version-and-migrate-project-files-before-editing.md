# Version and migrate project files before collaborative editing

Every native Project Format document carries an explicit Project Format Version that is independent of the mod version, Authoritative Revision, Extended Camera Animation JSON version, and Existing Runtime Camera Animation JSON. The server inspects this version before creating an editable Editing Session. A document already on the current version proceeds normally; a supported older version enters Project Format Migration; and a newer unsupported version enters a Newer-Format Read-Only State with a clear compatibility explanation.

Project Format Migration is server-authoritative, deterministic, and all-or-nothing. Before changing the active project file, the server durably retains the exact original document as a Migration Protection Checkpoint. It then converts and validates the complete document and uses the same temporary-file plus atomic-replacement discipline as ordinary project snapshots. Any parse, conversion, validation, persistence, or replacement failure leaves the original file active, retains recovery material, creates no partial migrated document or partial revision, and refuses to begin editable collaboration.

A successful migration is an explicit structural project change attributed to the participant whose open request initiated it. After the current-format document becomes active and the Editing Session is established, the migration appears as a new Authoritative Revision and one item in that participant's Personal Edit History rather than as an invisible disk rewrite. The Migration Protection Checkpoint is reference-protected while that history action or recovery state can still use it.

The initiating player may request Undo only while the migrated revision remains the latest accepted project change and no participant has made a later content edit. Undo does not make the old schema editable inside the current session: it restores the exact pre-migration document, closes the current editable session, and exposes that older document through Older-Format Read-Only State until a supported migration is explicitly requested again. If the migration has a later accepted edit, its history entry remains inspectable but is unavailable because its full-document footprint conflicts with subsequent collaboration. Redo repeats the migration from the protected older document and reopens the current-format editable session only after the new migration succeeds. A failed or cancelled compensation creates no partial revision and leaves the active document and session state unchanged.

Migration changes only the native Project Format document. It does not rewrite Existing Runtime Camera Animation JSON, Extended Camera Animation JSON, the Active Runtime Revision, exported client animation resources, or an active runtime camera instance. Runtime publication and compatibility import/export remain explicit separate actions.
