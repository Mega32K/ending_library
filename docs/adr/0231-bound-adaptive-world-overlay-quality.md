# Bound adaptive world-overlay quality

World-space camera overlays use the client-local `Adaptive Overlay Quality` policy to remain usable during long animations, dense node sets, complex scenes, and narrow performance margins. The policy has full, reduced-density, and minimal presentation levels and defaults to an automatic mode. Automatic selection responds to sustained frame-cost pressure with hysteresis so the editor does not oscillate between levels on individual frames. A manual quality choice may override automatic selection for the current client, but it never changes the project or collaborators' view.

Quality reduction affects rendering only. It may cull off-screen, distant, or low-priority unselected nodes; reduce trajectory sampling density; batch equivalent overlay geometry; simplify low-priority collaborator markers; and reduce nonessential visual detail. It must preserve the selected node, the current playhead neighborhood, the selected trajectory portion, Gizmo interaction, necessary hit targets, and enough surrounding context to explain the current edit. Selected hidden content continues to use the restrained Occluded Selection Trace contract rather than becoming a full-scene X-ray layer.

The policy never deletes, merges, retimes, rebases, or rewrites logical nodes and tracks. It never changes interpolation, easing, Bézier data, evaluated camera pose, preview playback, runtime playback, command-event timing, collaboration state, or server resource accounting. Timeline and curve virtualization remain the separate data-preserving mechanism for panel rendering; overlay quality does not substitute for or weaken that contract.

Quality state, frame-cost measurements, automatic transitions, and manual overrides are client-local and bounded. They are not sent to collaborators, stored in the Project Document or animation JSON, included in checkpoints or Undo/Redo, or retained after the relevant client lifecycle according to ordinary local view-preference cleanup.
