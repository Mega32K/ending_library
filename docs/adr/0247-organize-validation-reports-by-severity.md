# Organize validation reports by severity

A completed Cancellable Validation Run presents one read-only Validation Report whose header identifies its Validation Scope, terminal state, current or outdated status, complete Error, Warning, and Information counts, and any Details Limited state. Findings are grouped first by severity and then by stable diagnostic code rather than localized text; Whole Project reports further divide each diagnostic group by animation. Error starts expanded so blocking problems are immediately visible, while Warning and Information start collapsed to keep large reports readable.

Validation Severity comes from the finding's stable diagnostic definition and cannot be changed by the user, filtering, or localization. Group and header totals count all original finding instances; every retained expanded instance keeps its own target path and Validation Focus Result, different diagnostic codes never merge even when their localized text is similar, and a details-limited group states how many instances are retained out of its full total. Severity filters, text filtering, and group expansion change only the client-local presentation of that report; search matches localized diagnostic text, stable raw field identifiers, animation names, and target paths within retained details without changing totals, rerunning validation, reordering project content, or creating history. Selecting a finding changes only local editor focus or inspector navigation, never playback, the playhead, runtime state, project content, or Undo/Redo. Validation offers no automatic repair action and does not generate repetitive Information findings for checks that simply passed.
