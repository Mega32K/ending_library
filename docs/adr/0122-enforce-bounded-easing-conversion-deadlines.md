# Enforce bounded Easing conversion deadlines

Authoritative Easing-to-Bézier conversion uses separate server-controlled deadlines for queue wait and active computation. A queued request that exceeds its wait deadline is cancelled before execution; a running worker that exceeds its computation deadline is cooperatively stopped at bounded sampling, error-evaluation, and candidate-refinement checkpoints. A result is eligible for commit only when it completes before the deadline and reaches the server-thread terminal-state gate in time. Timeout, cancellation, and exception paths discard every partial candidate, do not retry automatically, and create no project revision, collaboration journal entry, or personal Undo/Redo item. The client may request a lower fidelity recomputation, but cannot extend or bypass the deadlines.
