# Freeze the last authorized view after permission revocation

When Reconnect Revalidation confirms that a player holds neither Project Owner nor Project Editor access, the current Project Tab remains open in `Permission-Revoked Inspection State` instead of closing without explanation. A change from Owner to Editor, or Editor to Owner, does not enter this state: the session resumes with the newly authoritative role and only the commands unavailable to that role are disabled.

Permission-Revoked Inspection State leaves the Editing Session, releases Collaborator Presence, command-event leases, pending lock claims, collaboration subscriptions, runtime-diagnostic subscriptions, and every other role-dependent server resource. The server sends no later Project Document updates through that tab. The client displays only the `Last Authorized Inspection View` it already possessed, marks it clearly as frozen and potentially stale, and does not imply that it represents the current authoritative revision.

The frozen tab permits local navigation, timeline seeking, property inspection, world-view observation, and isolated local preview of the Last Authorized Inspection View. It disables creation, mutation, Auto Key commit, Undo/Redo submission, checkpointing, saving, publication, Editor Animation Enable, project duplication, import/replacement, export of current project content, structured project clipboard extraction, lock acquisition, collaboration preview, and every other project-authorized operation. Closing the tab or reaching Connection Lifecycle Exit removes the frozen inspection surface according to the ordinary local lifecycle; it never creates a new server session.

Retained reconnect drafts become `Permission-Revoked Draft Material`. The Reconnect Draft Review Surface does not request or expose current authoritative field values after access is denied. For each affected draft it shows the last authorized baseline, retained local value, and permission-revoked reason, then permits only discarding it or retaining it as bounded client-local reference material. Retention does not reopen a Property Modal Surface, command editor, lock flow, or content operation. If access is later restored, the user must explicitly reopen and revalidate the project; only then may retained values be deliberately used to start a completely new ordinary edit against the current authoritative content.

The Project Tab Draft Dot may remain while Permission-Revoked Draft Material exists, but it never means the server will accept the draft. The Editor Status Bar gives the permission change action-required priority, states that the view is frozen and unsubscribed, explains which local material remains, and offers only valid detail, draft-review, tab-close, or explicit permission-recheck navigation. It does not poll continuously or restore access automatically.

Permission revocation is not a project revision, Undo/Redo item, checkpoint, or runtime publication. The frozen view and retained material are client-local, bounded, and cleared at Connection Lifecycle Exit. They do not grant access to later collaborator activity, project updates, server files, commands, diagnostics, or private drafts.

If a later permission check indicates that access has been restored, the editor shows an action-required notice but does not replace the frozen view or resume editing automatically. The player must explicitly invoke `Explicit Permission Rejoin`; that action performs fresh authorization, loads the current authoritative Project Document, and creates a new Editing Session only after identity, format, and permission validation succeed. Permission restoration never renews an old lock, revives released subscriptions, or silently applies Permission-Revoked Draft Material. A failed rejoin leaves the frozen inspection state intact, while retained drafts remain separate until the player deliberately adopts them through a new ordinary edit flow.

When `Explicit Permission Rejoin` succeeds, the existing frozen Project Tab is reused in place rather than opening a duplicate tab. The tab shell and its valid local workspace placement remain stable, while the Last Authorized Inspection View is atomically replaced by the freshly loaded authoritative Project Document and the tab enters the new Editing Session with the newly verified role. Content selections or navigation targets that no longer exist are cleared instead of being guessed, and Permission-Revoked Draft Material remains separate and unapplied.

If Permission-Revoked Draft Material still exists after that replacement, ADR-0207 immediately places the rejoined tab behind the grouped Reconnect Draft Review Surface. The new Editing Session remains read-only until every retained item has an explicit resolution and the whole resolution set is confirmed. No retained material bypasses this gate, while a rejoin with no retained material proceeds directly to ordinary editing.

The rejoin preserves only valid workspace observation state: the project-tab placement, panel arrangement, timeline viewport, graph/timeline mode, track expansion, and world-view camera are restored when their targets remain valid. For the selected animation, the playhead and valid selection identities are restored when that animation still exists; a playhead beyond the new duration is clamped to the new end, and missing animations, nodes, or fields clear their dependent selection and reset the playhead to zero. Rejoin never restores the previous playing state, never starts or enables a runtime camera, and never guesses replacement identities.

ADR-0211 binds permission validation, project validation, the returned Project Document, and the new Editing Session to one Atomic Rejoin Baseline. The tab remains read-only until that transaction completes. Concurrent collaborator changes are reflected through the stable authoritative revision selected by the server; the client never resumes from the frozen document, a partially loaded snapshot, or a locally guessed merge.
