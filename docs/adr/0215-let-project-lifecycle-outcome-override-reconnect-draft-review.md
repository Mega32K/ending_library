# Let project lifecycle outcome override reconnect draft review

When Reconnect Revalidation discovers that a project was archived or deleted while the player was in `Reconnecting Read-Only State`, the project lifecycle result takes precedence over ordinary stale-draft review. The client first discards every Retained Reconnect Draft for that project and then applies the authoritative lifecycle outcome: archive enters `Archived Inspection State` with only the last authorized inspection content already held by the client, while deletion enters `Deleted Project Notice` without exposing project content. No Reconnect Draft Review Surface is opened for that project, no retained value is automatically adopted, and no project, personal history, lock, runtime, or export operation is created.

The rule is terminal for the affected reconnect attempt: later collaborator edits, a later archive/restore race, or a delayed operation acknowledgement cannot resurrect the discarded drafts or reopen the old Editing Session. A restored archived project requires an explicit fresh open or `Explicit Permission Rejoin` against a new `Atomic Rejoin Baseline`; a deleted project can only be reopened if a separate server-supported recovery operation creates a new project identity, never through the old tab. Other projects in the same connection lifecycle continue through their own independent Reconnect Revalidation and draft-review paths.
