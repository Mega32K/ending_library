# Keep markers in project format only

The design distinguishes the complete collaborative project document from Existing Runtime Camera Animation JSON, the current per-channel resource format consumed by the runtime reader. Project-format export serializes only the selected server-accepted revision and includes marker stable identities, normalized names, times, and project metadata, while excluding local editor workspace state and uncommitted drafts. Importing that project format into a new project regenerates marker stable identities and validates the complete marker set against the shared resource budget before committing.

Existing Runtime Camera Animation JSON remains a compatibility and runtime-facing format. It contains animation and keyframe fields understood by its reader but has no project-marker representation; exporting to it omits markers, and importing it never invents markers. Copying a project content range may explicitly include markers in that range; pasted markers receive new stable identities, use the selected time offset, and are accepted only as one budget-checked all-or-nothing operation. No marker data is written to client runtime animation files.
