# Use one shared preview stage for collaborative trajectory visualization

The editor evaluates and renders camera trajectories against one project-level Preview Stage. Absolute `X/Y/Z` channels remain world-space values; relative `RELATIVE_X/Y/Z` channels are transformed through the stage orientation, matching the runtime camera basis rather than each participant's live player pose. The current observer may orbit or follow the stage locally without changing the stage or the project. When a Collaborative Preview starts, it captures a `Collaborative Preview Stage Snapshot` so every joined participant evaluates the same spatial basis for the lifetime of that preview.

A Stage Capture action explicitly records an observer's current camera reference as the stage. Capturing the stage is separate from inserting animation keyframes, and stage changes are collaborative project metadata rather than player capability state. A stage edit received while a Collaborative Preview is active updates the live Project Document and active editing participants, but does not change the preview's stage snapshot. The Preview Leader may invoke an explicit validated `Preview Stage Switch` to pause, apply the new stage to every joined participant, and resume under one synchronized transition; no ordinary stage edit causes an implicit trajectory jump. The stage representation is not emitted as a legacy animation field; legacy export either omits it with a clear notice or uses the selected conversion context.
