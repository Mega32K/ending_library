# Mark inactive tabs after successful reopen

When a `Reopen Project` request commits successfully after its originating tab has lost focus, the tab changes from archived styling to ordinary inactive project styling and removes its `Archived Reopen Indicator`. It then shows one temporary blue `Inactive Reopen Success Indicator` so the player can distinguish a completed reopen from a tab that is merely eligible to reopen. The marker is independent from the `Project Tab Draft Dot` and never represents unsubmitted content, persistence state, Presence, locks, live subscriptions, preview playback, or runtime activation.

The successful result applies only to the original still-open tab and does not activate it, switch panels, change the current project's selection, or open a world preview. The reopened tab remains an inactive local container until the player deliberately focuses it. Focus immediately shows the tab and enters `Focus-Time Reopen Revalidation State`: the already loaded authoritative document remains visible, a lightweight status explains validation, and all mutation, history, Auto Key, lock, publication, runtime-enable, playback-restoration, and camera-takeover actions remain disabled. Current permission, lifecycle, format, document-baseline, and active-tab validation then runs without a blank page or blocking modal. Successful validation clears the marker and joins the live Editing Session; failure replaces the marker and tab state in place with the applicable archive, deletion, permission-revoked, transient, or format outcome. Switching away may cancel validation before its commit boundary.

The indicator is player-local, bounded to the current Connection Lifecycle, and is cleared when the tab closes or the lifecycle ends. It is never written to the Project Document, animation JSON, checkpoint history, project metadata, or personal Undo/Redo history.
