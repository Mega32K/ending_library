# Add a Blockbench-style graph editor and timeline controls

The bottom timeline provides a real Graph Editor Mode inspired by the supplied Blockbench reference. A user can switch between compact timeline presentation and value-versus-time curve presentation with the dedicated graph-editor control and its `F3` shortcut. In graph mode, vertical keyframe movement edits the authored scalar value through the normal edit-gesture, Auto Key, validation, collaboration, and Undo/Redo rules. Intervals between neighboring keys render their actual curve data, and channel-family components use semantic RGB-like ordering for X, Y, and Z while unselected curves reduce opacity rather than disappearing. The graph automatically fits the visible numeric range with padding and a useful zero line when applicable, while retaining manual vertical zoom, vertical pan, horizontal time navigation, and an explicit return-to-auto-range action. These view settings are player-and-project workspace state and never modify animation values.

The timeline also exposes an editor-only channel-visibility menu. Rotation, position, and command channels can be individually shown or hidden for the current view; scale is not a supported channel, and hiding empty channels is a separate display filter. Visibility changes never alter runtime behavior or project content. The clear-timeline command removes only the selected item's timeline data according to the normal deletion and transaction rules, while the population command adds all non-empty scalar tracks and command-effect rows from the currently edited animation to the timeline's logical display set without duplicating entries or creating or changing animation data; channel filters may leave an added row visually hidden. The left tool cluster is ordered as Graph Editor, channel visibility, clear selected timeline tracks, populate current animation, create Command Animation Effect Event, and set marker. The right transport cluster keeps previous navigation, local play or pause, and next navigation immediately available. The toolbar and tooltips must be compact, responsive, and fully operational rather than decorative.
