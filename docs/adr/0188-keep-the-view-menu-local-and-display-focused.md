# Keep the View menu local and display-focused

The top toolbar exposes a View Menu dedicated to the current client's display and workspace state. It controls auxiliary panel visibility, Workspace Preset application, default-layout restoration, Timeline Presentation Mode, world-space trajectory and guide layers, collaborator indicators, focus-to-content actions, and entry or exit from Immersive Preview. Every command has an explicit local-state binding and visible enabled or disabled reason.

View commands never mutate the Project Document or its accepted revision. They do not create an Edit Operation, enter personal Undo/Redo, publish or stop a runtime revision, save or restore a checkpoint, or change another participant's view. Switching timeline presentation mode preserves authored data, selection identities, playhead, playback state, and current project content.

Trajectory lines, world-space keyframe nodes, Gizmo handles, camera frustum, guides, target connections, Preview Stage axes, and collaborator indicators are View Display Layers rendered in the existing Game Frame Preview or Abstract Stage Preview. The Viewport Control Bar exposes the most common layers through the same state model, while the View Menu remains the complete labeled list. Toggling a layer changes only local rendering; it never deletes tracks, hides data from collaborators, changes server subscriptions, or alters runtime camera behavior. Both entry points reflect each layer's current state with semantic labels, icons, checkmarks, and accessible feedback rather than color alone.

The View Menu remains separate from File and Settings. File owns project lifecycle and persistence, Settings owns device-persisted editor preferences, and View owns the active local presentation. Active View Display Layers are captured as Project View State in Project Workspace Layout when the editor closes or a Project Tab switches, subject to the existing connected-lifecycle boundary. They are not written to the Project Document or Device Preference Store merely because they changed. Settings owns a separate Default View Layer Profile plus the explicit Promote Current View Defaults action.
