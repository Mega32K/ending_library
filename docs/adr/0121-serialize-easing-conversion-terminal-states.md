# Serialize Easing conversion terminal states

Each Easing-to-Bézier confirmation request has exactly one server-authoritative terminal state: cancelled, committed, rejected, or failed. Cancellation wins whenever the request has not entered the server-thread atomic commit section; a result that arrives after cancellation is discarded. Once atomic commit begins, cancellation cannot interrupt or roll back that transaction, and the client receives the committed result instead. Closing the editor, disconnecting, losing authorization, or stopping the project only requests cancellation; a late asynchronous callback can never mutate the project after the request has become inactive. Terminal cleanup of the task handle, immutable snapshot, and queue references is idempotent and occurs exactly once.
