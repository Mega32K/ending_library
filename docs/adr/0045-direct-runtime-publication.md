# Make publication directly control the runtime revision

Runtime publication is not split into separate publish and apply/start permissions or phases. A Project Owner or Project Editor explicitly publishes a selected valid project revision, and that action directly makes the revision active for camera runtime execution; the same authorized runtime controls may replace the active revision or stop the runtime application. This preserves the previously chosen two-role permission model and avoids an extra pending-publication state that could make the editor report success while the game still uses an older revision.

The publication operation is server-authorized, revision-specific, auditable, and independent of local editor preview. It is a Lock-Neutral Project Operation: publication may proceed while command events are being edited, but only the selected server-accepted revision becomes active and no uncommitted command draft is included or discarded. It does not move the player, enter Immersive Preview, or silently alter the editor's working revision. A later edit creates a newer project revision but does not change the Active Runtime Revision until another explicit publication occurs.

The Animation Publication Command Group is the primary editor surface for publish, active-revision replacement, and project-runtime stop. Each attempt creates a bounded Runtime Publication Record with its actor, time, requested accepted revision where applicable, operation type, and outcome. Publication records do not enter Personal Edit History and cannot be undone through `Ctrl+Z`.
