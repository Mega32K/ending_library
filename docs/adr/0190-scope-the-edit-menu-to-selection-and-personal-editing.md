# Scope the Edit menu to selection and personal editing

The top toolbar exposes a focus-aware Edit Menu containing personal Undo, personal Redo, Cut, Copy, Paste, Duplicate, Delete, Select All, Deselect All, and Invert Selection when each command is valid for the active Panel Focus and selection domain. The menu, shortcuts, context menus, and Command Palette invoke the same command registrations and therefore share availability, disabled reasons, permission checks, lock rules, and transaction behavior.

Undo and Redo use the current player's Personal Edit History and the established compensating-operation protocol. Selection commands change only local selection state and create no project revision. Plain click replaces a node selection, `Ctrl` plus left click adds or toggles nodes, and `Shift` plus left click removes nodes; `Shift` is not a range-selection shortcut. Select All and Invert Selection remain bounded to the active compatible selection domain rather than mixing markers, keyframes, command events, tracks, and unrelated panel rows into one ambiguous set.

Copy creates a client-local Structured Editor Clipboard payload from server-accepted content. It may contain compatible keyframes, tracks, curve nodes or segments, command events, markers, or other explicitly supported editor structures, preserving relative timing and structural relationships without copying stable project identities as reusable target identities. Copying a Command Animation Effect Event locked by another participant reads only its latest accepted content and never exposes the holder's draft.

The Structured Editor Clipboard remains available across Project Tabs only during the same connected editor lifecycle and is held in bounded client memory. World/server exit or disconnection clears it. The editor never writes structured project content or command-event data to the operating-system clipboard; ordinary text fields keep normal system clipboard behavior, and an explicit Copy as JSON command is the only external serialization path.

Cut first produces a valid clipboard payload and then submits one all-or-nothing delete transaction. If serialization fails, no delete is attempted. If the server rejects deletion because of permission, stale state, structural validation, or a command-event lock, the project is unchanged and the copied payload remains available. A successful deletion is one authoritative revision and one personal Undo/Redo item; clipboard creation itself is not a project operation.

Paste and Duplicate begin as local Paste Preview Drafts. The preview resolves target animation, scalar tracks, Additive Lanes, relative time offset, required parent structure, resource budgets, command-event locks, and all overwrite targets. It does not create shared placeholder objects. Explicit confirmation submits the complete insertion or replacement as one server-authoritative transaction and one Undo/Redo item; rejection leaves the project unchanged and retains the preview for correction where its baseline remains valid.

Copy and Cut enforce a finite Clipboard Resource Budget covering payload size, item count, nesting depth, and command-event text. An over-limit copy fails without replacing the previous valid payload; a successful replacement releases the old payload before retaining the new one. Pasting into another Project Tab repeats complete Cross-Project Paste Validation and never transfers source stable identities, locks, permissions, or uncommitted drafts.

Delete follows the established scope rules: ordinary selected timeline items use direct undoable deletion, while animation deletion, track clearing, broad structural deletion, replacement import, checkpoint restoration, and other destructive lifecycle actions retain their dedicated confirmation or preflight. The Edit Menu never contains save, checkpoint, publication, restore, archive, project import, or export actions.
