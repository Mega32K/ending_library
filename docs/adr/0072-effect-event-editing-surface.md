# Edit timed effects as discrete event points

An uncommitted command-event draft that becomes stale during reconnection is resolved through ADR-0207 before command editing resumes; choosing `Keep as New Re-edit Draft` still requires fresh event identity, permission, validation, and Command Event Personal Edit Lock acquisition.

The command properties editor is a Property Modal Surface under ADR-0203. Its completion list is an Anchored Utility Surface, so it closes or refreshes independently without bypassing the event lock or committing the surrounding draft.

The timeline's Effect Event Editor presents only Command Animation Effect Events as discrete point events in a collapsible Effects group. Each event has a stable identity, editable time, explicit Same-Time Effect Order, exactly one normalized command payload, and validation state. Users can create events from the toolbar or row add controls, select, drag, duplicate, copy, paste, open a responsive properties popup, request server-authoritative command completion, and delete them. Copy reads only the latest server-accepted event content, including when the source is locked; paste creates a new local Command Event Creation Draft at the current playhead time and does not copy an uncommitted draft or immediately mutate the project. Opening the command properties editor acquires a temporary Command Event Personal Edit Lock for that event. If another participant holds the lock, the same properties surface opens as a Locked Command Event Read-Only View: it shows the last server-accepted values and holder identity, disables all mutation and completion controls, creates no local draft, and offers an explicit `Enter Edit` action only after a later lock acquisition can succeed. The lock covers its command text, authored time, same-time order, deletion, replacement, and any structural operation that mutates the event; other participants can inspect it but cannot modify any protected part until release. The lock remains held after validation failure so the holder can correct the local draft, and it is released by confirmation, cancellation, properties-editor closure, project switching, editor closure, lifecycle exit, or server-side lease expiry. Completion edits only the local draft; it never executes a command or bypasses final validation. The completion menu is transient: it appears after debounced edits while the field is focused, supports `Ctrl+Space`, keyboard navigation, `Tab`/`Enter` acceptance, and `Esc` dismissal, and discards stale results without blocking ordinary editing. A completion applies only to the server-provided replacement range; if that range is unavailable or invalid, only the current cursor word may be replaced. When the menu is open, the first `Enter` accepts the suggestion and a subsequent `Enter` confirms the dialog. Multiple command events may share one timestamp and must remain distinct. Batch mutations over selected command events use one server-authoritative all-or-nothing preflight: a missing, stale, unauthorized, or differently locked event rejects the complete batch, reports the blocking event and holder when applicable, and never silently skips it; a successful batch creates one accepted revision and one personal Undo/Redo item. Ordinary Delete on selected command events submits directly without a confirmation dialog, preserves the playhead and timeline focus, clears the deleted selection, and records one Undo/Redo unit; it is rejected as a whole when a selected event is locked, stale, unauthorized, or still has an uncommitted local command draft. The editor does not expose controls for any other effect-event type or a multiline command-list payload.

Event changes use the same permission, server validation, conflict footprint, transaction, and personal Undo/Redo rules as other project edits. Starting a new event creates only a private client-local Command Event Creation Draft with a temporary local identity; it is not broadcast, persisted, revisioned, or locked. The popup permits that draft to be temporarily empty, incomplete, or invalid while the user is typing, but confirmation is enabled only after authoritative validation succeeds. One successful server confirmation atomically validates the complete payload, resolves conflicts, assigns the stable event identity, creates the shared event and authoritative project revision, and records one personal Undo/Redo item. Rejecting an edit preserves the previously shared event; cancelling or abandoning a new event discards the draft without an empty event, project revision, lock, or Undo/Redo entry. The visual surface must be fully functional and responsive, not a point-only mock.
