# Make responsive layout a global editor constraint

The rewritten Camera Animation Editor is built on a Responsive UI Framework from its lowest layout layer upward. Responsiveness applies to the entire editor, not only the Workspace Shell or Animation Properties Popup: top menus, dockable panels, preview viewport, timeline, curve editor, inspectors, context menus, dialogs, toolbars, labels, hit targets, overlays, and status surfaces must derive their placement and size from available content bounds, insets, relative weights, minimum and maximum constraints, and explicit breakpoints. The implementation must not use Minecraft's original absolute screen coordinates as its layout model.

At smaller or unusually shaped window sizes, the editor substitutes drawers, collapsible groups, tabs, stacked controls, or simplified density rather than shrinking content until it overlaps, clips, or becomes unusably large or small. Typography, icons, keyframe nodes, spacing, and interaction targets use bounded scaling. The Blockbench-inspired visual language remains consistent across every responsive state, and the final rewrite prompt must describe these responsive rules as foundational UI architecture rather than as an optional polish pass.
