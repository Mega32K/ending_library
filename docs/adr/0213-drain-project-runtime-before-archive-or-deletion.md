# Drain project runtime before archive or deletion

Project archive and deletion include a server-authoritative `Project Runtime Lifecycle Drain` in the same destructive preflight and commit boundary as lock invalidation and tab closure. The preflight reports a bounded summary of affected running Project Runtime Instances, target players, and the current Active Runtime Revision before the owner confirms the operation. On a successful commit, every affected runtime instance is stopped and the project's Active Runtime Revision is invalidated before the archive or deletion outcome is exposed to clients. Each online target then receives the non-blocking Camera Restoration Delivery defined by ADR-0214, which applies its Camera Restoration Snapshot or safest verified player-camera fallback without holding the lifecycle transaction open. Archive preserves the finite publication and project-history records but does not reactivate or republish a revision when the project is restored; deletion clears the active runtime reference and retains only the bounded lifecycle/deletion audit required by the project history policy. A failed preflight or commit leaves runtime instances, camera state, active revision, tabs, locks, and drafts unchanged; after commit, a missing client acknowledgement cannot roll the lifecycle result back. The drain is not a personal Undo/Redo operation and cannot leave a project archived or deleted while its old runtime remains active.
