# Close open tabs after project archive or deletion

Project archive and deletion use the existing Destructive Project Preflight and Destructive Project Lock Drain, plus the Project Runtime Lifecycle Drain defined by ADR-0213. Before confirmation, the owner sees a bounded summary of affected running runtime instances, target players, and the current Active Runtime Revision. When archive commits, every open tab for that project atomically leaves its Editing Session, releases Presence, subscriptions, command-event leases, and pending lock claims, discards unsubmitted drafts, and enters `Archived Inspection State` with the last authorized Project Document already held by that client. The archived tab remains navigable for timeline inspection, property viewing, world-view observation, and isolated local preview, but cannot edit, submit, Undo/Redo, checkpoint, publish, enable runtime animation, acquire locks, or export current content. Restoring the project never revives these tabs or runtime instances automatically: the owner restores it through the Project Browser, and each player may then use the tab's explicit `Reopen Project` action to perform a fresh open or rejoin against a new Atomic Rejoin Baseline before explicitly publishing or starting runtime when needed.

When deletion commits, every open tab for that project atomically releases the same session resources and discards unsubmitted drafts, then replaces its content view with a bounded `Deleted Project Notice` containing only the project identity and deletion metadata needed to explain the closure. The notice offers close only; it does not retain or expose the deleted Project Document, allow preview or export, or create a personal Undo/Redo entry. The runtime drain and tab transition are one lifecycle result: clients never observe a deleted project with an old camera instance still active. A failed preflight or commit leaves the original tabs, locks, drafts, editing sessions, runtime instances, and active revision intact. Archive and deletion are project-lifecycle operations rather than personal edit-history entries, and their effects are visible through the server's bounded project lifecycle/history surfaces.

The same lifecycle result outranks a reconnecting client's retained drafts. Reconnect Revalidation applies Archived Inspection State or Deleted Project Notice first and clears the affected retained drafts without opening ordinary stale-draft review. A project restored later must be explicitly opened or rejoined from current server state; a deleted tab cannot recover its former document or drafts.
