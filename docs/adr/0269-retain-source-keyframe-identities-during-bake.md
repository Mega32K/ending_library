# Retain source keyframe identities during Bake

Every valid source scalar keyframe inside the closed Bake Time Scope already supplies a mandatory sample time, so Bake reuses that keyframe as a Retained Bake Keyframe instead of deleting and recreating it. The node keeps its stable identity, canonical time, and Additive Lane membership, while its value becomes the exact pre-Bake lane evaluation at that time and its in-scope interpolation and curve data are replaced under the accepted LINEAR/CONSTANT output rules. A Bake Boundary Anchor additionally retains its established outside-facing curve semantics.

Only adaptive or fixed-interval sample times without an existing keyframe create new node identities. The Tool Operation Preview distinguishes retained source nodes from generated samples. A retained node referenced by the player's current selection or inspector remains addressable and selected after commit, while generated nodes are not automatically mass-selected. Existing duplicate nodes at the same canonical time in one Additive Lane make the source invalid and block Bake rather than selecting an arbitrary survivor or merging identities.

Commit-time validation rechecks every retained identity, time, lane, and source value; a concurrent change invalidates the preview and causes complete rejection. The atomic Bake and personal Undo/Redo item restore all retained nodes' original values, interpolation, active and dormant curve data, selection-addressable identities, and boundary semantics while removing every node generated by that Bake. This preserves collaboration and UI continuity without preserving curve content that Bake deliberately replaces.
