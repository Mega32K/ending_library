# Store timeline markers in the project file, not animation JSON

The editor provides a Set Marker command that creates a marker immediately at the current animation time only when the playhead is not at the animation start. It does not open properties first or create a client-local ghost: one server-authoritative transaction validates permission, expected revision, the per-animation Marker Resource Budget of `4096` markers by default, and the time boundary, assigns stable identity and the next generated default name, creates one project revision and one personal Undo/Redo item, then selects the accepted marker locally without changing playhead or playback state. The same budget applies to every marker-creating path, including duplication, paste, import, and checkpoint restoration; an operation that would exceed it is rejected as a whole without truncation or automatic deletion. At time zero the command is disabled with an explanatory tooltip; rejection creates no placeholder or empty revision and reports its bounded reason through the editor status surface. Multiple markers may share the same time. A project may contain multiple stable-ID markers; each marker can be named, moved, selected, and deleted independently. A Project Timeline Marker is shared project-level metadata, not a numeric keyframe, runtime Animation Effect Event, Existing Runtime Camera Animation JSON field, or client runtime animation-file entry. Marker edits are collaborative project operations and personal Undo/Redo targets. It is persisted with the project file and excluded from exported/client animation data.

Clicking a marker seeks the local editor preview immediately. If playback is paused, the preview remains paused after the seek. If the animation has not started or has already ended, activating a marker moves the playhead there and enters playback. A currently playing animation remains playing after the seek. Marker editing uses a separate Marker Selection rather than joining the keyframe, curve-node, or command-event Selection Set. Plain left click selects and seeks; `Ctrl` plus left click adds or toggles a marker without seeking; `Shift` plus left click removes a marker without seeking; double left click opens the marker properties surface; dragging previews a time change locally and submits it on release; right click opens a compact marker menu; and clicking empty marker space clears only Marker Selection. Marker interactions do not display hover-only controls. Double-clicking opens a responsive marker properties popup, selects the existing name text, and edits name and exact time through a private Marker Properties Draft. Names trim leading and trailing whitespace, must be nonempty, single-line, control-character-free, and within the finite UI-safe limit; duplicate names are allowed. Times must be finite, strictly greater than animation start, and no later than the current finite Animation Duration; duplicate times are allowed. Local feedback runs immediately and the server repeats these checks at confirmation. Opening the popup does not acquire a personal lock or broadcast intermediate values; confirmation submits only changed fields against its baseline, permits disjoint concurrent field merges, and rejects same-field or deleted-marker conflicts while retaining the draft for correction. `Esc`, cancellation, or popup closure discards the draft. A successful property commit creates one authoritative revision and one personal Undo/Redo item. Deleting a selected marker submits directly without a confirmation dialog, preserves the current playhead and playback state, and creates one authoritative revision and one personal Undo/Redo item; rejection preserves both the marker and its selection. Marker creation, movement, deletion, activation, and property editing must be fully functional rather than placeholder controls.
