# Show collaborator presence without introducing editing locks

During a Transient Connection Interruption, presence and remote gesture previews may expire and are rebuilt only from current authoritative session state after Reconnect Revalidation; the client never treats retained remote presence as a draft or collaboration guarantee.

An active editing session broadcasts lightweight Collaborator Presence: stable session color, display name or initials, selected track and keyframe, playhead, local observation camera, and an optional Gesture Preview while a participant is dragging or shaping an edit. Presence is scoped to the active session, expires immediately when the participant leaves or disconnects, and is never stored in the Project Catalog, Project Document, animation JSON, Undo/Redo history, or authoritative revision.

Presence does not reserve or lock content. Multiple participants may act on the same keyframe. A remote Gesture Preview is explicitly translucent and non-authoritative; only the accepted server operation changes the shared document, while rejection removes the preview and explains the conflict. The server allows a deliberately generous but finite number of participants and active previews per session, and each participant's presence rate and payload size are separately bounded. Newer presence replaces older presence from the same sender, expired entries are removed, and excess awareness data is dropped or rejected without affecting authoritative project content. Presence limits are independent from content-operation limits so a large preview cannot consume the edit budget.

The bottom Editor Status Bar shows only the bounded online-collaborator summary needed for normal awareness. Opening its Collaboration Status Area reveals the current session's read-only participant and presence details without selecting their content, following their camera, moving the local playhead, joining Collaborative Preview, or creating project history. The compact Workspace Bar Status Entry may reflect collaborator activity only through the shared Status Priority State; it does not maintain a separate presence model.
