# Separate ordinary save from named checkpoint creation

The File menu exposes two related but distinct persistence actions. File > Save, also bound to `Ctrl+S`, is Project Save: a Lock-Neutral request to flush the server-accepted Operation Journal and create an atomic Project Snapshot. It has no naming step, creates no separately user-visible retention entry, does not change project content, and does not enter personal Undo/Redo. It never confirms Animation Properties, Auto Key, Command Event Creation, or any other local content draft.

File > Create Checkpoint opens a responsive Checkpoint Creation Dialog. The dialog shows a default date-and-time-based name with the current text selected, accepts an optional description, and confirms only a Named Project Checkpoint label for the server-accepted state. The server first completes the accepted-content flush, then writes the label atomically with its immutable target Revision Commit Node, creator, creation time, and the normal finite retention references. A failed flush or label write leaves the active project, local drafts, and prior checkpoints unchanged; no partial named checkpoint is exposed.

The checkpoint name is validated as a non-empty, project-wide unique name under trimmed case-insensitive comparison. Multiple differently named checkpoints may point to the same accepted revision and share its durable reconstruction anchor. File > Create Checkpoint always targets the current accepted head; creating a checkpoint on an older available revision is a separate Project History and Recovery Panel action and never changes the active project state.

Both actions preserve playhead, playback, selection, workspace layout, active command locks, and personal Undo/Redo. Local content drafts remain outside the saved/checkpointed document and keep the Project Tab Draft Dot until accepted, cancelled, or discarded. Named checkpoint creation is not itself an authoritative project-content revision, while later restore or deletion continues to follow the owner-authorized lifecycle and conflict rules.
