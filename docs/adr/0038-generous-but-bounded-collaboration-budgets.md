# Use generous but bounded collaboration resource budgets

The first editor release targets substantial camera animations and several simultaneous editors, so resource limits must not be tuned as minimal-demo limits. The server uses a centralized, configurable Collaboration Resource Budget with deliberately generous values for the intended workload. Exact default numbers are implementation and load-test decisions; the design requirement is that every budget remains finite and is measured before the corresponding state is allocated.

Budgets are independent rather than one shared counter. They cover at least active participants and sessions, the single active Collaborative Preview permitted per Project, live Collaborator Presence entries, active Gesture Previews, presence update frequency and payload size, Edit Gesture Transaction target count and serialized size, project structure counts such as scalar tracks, Additive Lanes, and keyframes, and the pending Operation Journal size before compaction or a forced Project Snapshot. A large permitted project must not make per-packet, per-player, or per-session buffers unbounded.

The server validates declared counts and byte sizes before fully decoding or materializing client-provided collections. An over-limit content transaction is rejected atomically with a specific reason; it is never silently truncated, partially applied, or retried against a different baseline. An over-limit presence update may be coalesced, dropped, or rejected because presence is non-authoritative. Structural imports and project creation validate the complete proposed size before mutating the Project Document.

Limits are server-authoritative and are not relaxed by client claims. Diagnostics should identify which budget rejected an input without logging unbounded payload data. Expired presence, completed previews, and journal entries covered by a valid snapshot are reclaimed through their normal lifecycle paths, so generous limits increase usable capacity without turning long-lived server state into an unbounded memory or disk sink.
