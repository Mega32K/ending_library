# Model every camera modifier as an independent scalar track

The project document stores one independent scalar animation track for each supported camera `ModifierType`. Each scalar track may contain multiple named Additive Lanes. A lane preserves one legacy `keyframes` group and is evaluated independently; the lane results are then added together for that scalar track, matching the current runtime behavior. Related channels may appear inside visual groups such as position, relative translation, rotation, and lens controls, but a group does not become an additional animated value or replace the underlying tracks. Multi-axis and other linked editor gestures are translated into coordinated edit operations against the affected scalar tracks and their selected lanes.

The default legacy group maps to the default lane. Non-default legacy group names are retained as lane names during import and emitted again during compatible export. A new keyframe is written to the currently active lane, and a lane is never silently merged with another lane merely because timestamps match. This model maps directly to the current camera manager and legacy animation data, keeps interpolation unambiguous for every value, and allows track identity, color, visibility, locking, curve display, and future editor metadata to evolve without introducing a second vector-valued animation representation.
