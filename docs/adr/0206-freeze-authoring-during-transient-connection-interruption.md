# Freeze authoring during transient connection interruption

When one or more retained drafts fail Reconnect Revalidation, they are resolved together through the Reconnect Draft Review Surface in ADR-0207 rather than through sequential dialogs.

If permission revalidation returns neither Project Owner nor Project Editor, the client follows ADR-0208 instead of entering ordinary stale-draft review: it leaves the Editing Session and freezes the last authorized content as a Permission-Revoked Inspection State.

The Camera Animation Editor distinguishes a temporary `Transient Connection Interruption` from a definitive `Connection Lifecycle Exit`. A transport interruption enters `Reconnecting Read-Only State` only while the client remains in the same world and editor context and a bounded attempt to restore the same connected lifecycle is active. Explicit disconnect, world or server exit, shutdown, user cancellation, reconnection expiry, or rejection of the prior session identity becomes Connection Lifecycle Exit and performs the already established session cleanup.

Reconnecting Read-Only State keeps the current project tabs, Current Edited Animation, playhead, timeline and graph viewport, panel layout, selection where still locally meaningful, and unsubmitted property, marker, or command drafts. The Project Tab Draft Dot continues to identify retained local content. The editor disables all server-authoritative mutation paths, including content submission, Auto Key commit, Undo/Redo compensation, checkpointing, publication, project lifecycle changes, lock acquisition, command completion that requires the server, and destructive operations. Viewport observation, timeline inspection, and isolated local editor playback may continue, but they cannot create server state or be presented as synchronized collaboration.

An active continuous Gesture Preview is cancelled to its pre-gesture baseline when interruption begins because an in-progress pointer gesture has no safe authoritative commit boundary. A submitted but unacknowledged operation is not blindly resent or treated as rejected. Reconnect Revalidation asks the authoritative session for its outcome using the operation's stable request identity or equivalent idempotent correlation; an already accepted operation is applied once, while a request with no accepted outcome becomes an explicit local proposal rather than an automatic retry.

Collaborator Presence and remote Gesture Previews expire normally while transport is unavailable and are rebuilt from current authoritative session state after reconnection. A Command Event Lock Lease is never assumed to survive: the server may release it through missed heartbeat expiry, while the client may retain the command text only as a Retained Reconnect Draft. Editing that command resumes only after explicit lease reacquisition and validation against the current event identity and revision. Another holder, changed event, removed event, permission change, or stale baseline keeps the surface read-only and exposes only valid recovery choices.

Successful transport restoration performs Reconnect Revalidation before authoring resumes. It refreshes the participant's Owner or Editor permission, project lifecycle and format state, authoritative revision, selected object identities, outstanding operation outcomes, command locks, and every retained draft baseline. Unchanged or semantically compatible drafts may return to an editable state. A stale or conflicting draft is never auto-merged or auto-submitted; the user explicitly chooses to refresh from authoritative content, discard the retained draft, or start a new re-edit flow using retained values where the current permissions, identities, lock state, and validation rules permit it.

Project lifecycle state is resolved before ordinary draft review. If a project was archived while the client was reconnecting, ADR-0215 discards that project's retained drafts and enters Archived Inspection State; if it was deleted, the client enters Deleted Project Notice and exposes no project content. The reconnecting client never delays, bypasses, or reverses the committed archive/deletion result in order to preserve a local draft.

The Editor Status Bar gives reconnecting and revalidation the highest connection-state priority, shows the workspace as read-only, and provides bounded detail and cancellation. Successful recovery or terminal failure may use one Transient Status Notice after the state transition. Reconnection does not replay missed presence or session notifications as durable history. A terminal Connection Lifecycle Exit clears project workspace snapshots, retained reconnect drafts, personal Undo/Redo history, session notifications, transient notices, presence, and local lock claims exactly as the prior lifecycle rules require.

A player who later joins a world or server after Connection Lifecycle Exit begins a `Fresh Connection Re-entry`, not a continuation of the former editor lifecycle. No project tab, selected animation, playhead, timeline viewport, panel layout, selection, draft, personal history segment, transient notice, Presence state, subscription, lock, pending operation, preview playback, or Project Runtime Instance is restored from the prior connection. The editor does not open or rejoin a project automatically; the player explicitly opens the editor and chooses an authorized project, which is loaded from current server state with fresh permission validation. Server-persisted projects, checkpoints, catalog metadata, and Active Runtime Revision remain available according to their ordinary persistence rules, while player-local Global Editor Preferences such as theme and shortcut profile may persist because they are not connection-scoped project workspace state.
