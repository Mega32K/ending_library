# Navigate curve fields with numeric-keypad directions

Curve Segment Inspector fields use the physical left and right keys on the numeric keypad as the dedicated previous-field and next-field gestures. With NumLock enabled the platform may report these as Numpad 4 and Numpad 6; with NumLock disabled it may report keypad Left and Right. The editor normalizes both representations to the same logical actions. The left gesture validates and confirms the current field before focusing the previous ordered field; the right gesture performs the same operation before focusing the next.

Main-keyboard left and right arrow keys retain standard caret movement inside the active text field. `Tab` remains available for normal accessible UI focus traversal, but it is not the dedicated curve-coordinate navigation shortcut. If the current value is invalid, empty, malformed, non-finite, or outside its allowed range, focus remains in that field, the error is shown visibly, navigation is blocked, and no server operation or Undo/Redo entry is created.

A successful keypad transition commits the complete logical field edit, including any required `AUTO` to `ALIGNED` promotion and coupled-neighbor changes, as one atomic transaction. Moving through multiple fields therefore creates one Undo/Redo item per confirmed field unless a separately defined grouped-edit interaction is active.
Field navigation is bounded rather than cyclic. Pressing the physical keypad-left gesture while the first ordered field is focused confirms a valid edit but keeps focus on that first field. Pressing the physical keypad-right gesture on the last field behaves equivalently. The field gives a restrained boundary indication without an exaggerated animation, and focus never wraps from the last field to the first or from the first field to the last.
