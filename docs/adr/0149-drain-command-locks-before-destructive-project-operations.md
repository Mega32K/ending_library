# Drain command locks before destructive project operations

Project operations are divided by whether they can operate solely on a server-accepted revision. Save or Durable Checkpoint creation, export, and Runtime Publication are Lock-Neutral Project Operations: they proceed without waiting for command locks, exclude every uncommitted draft, and leave active leases untouched. Their UI must identify the accepted revision being saved, exported, or published so an open command draft is not mistaken for included content.

Project deletion, archive, checkpoint restoration, replacement import, and removal of the editor permission of a current lock holder are destructive with respect to active command drafting. Their first attempt is blocked when affected Command Event Lock Leases exist and shows the owner the affected events, holders, and explicit consequence that those uncommitted drafts will be lost. The ordinary `Request Release` mechanism remains available, but the Project Owner may instead confirm `End Related Editing and Continue` for the global operation. This is not lock takeover: no draft becomes visible or transferable, and no event enters the owner's edit mode.

After confirmation, the server first enters a reversible Destructive Project Preflight. It establishes a short project mutation barrier and prevents new affected lock acquisitions or content mutations, but retains the existing leases and local drafts. The server settles already in-flight operations and validates authorization, target identities, expected revision, checkpoint or import inputs, migrations, resource budgets, candidate serialization or staging, and every other precondition that can be checked before draft loss. If preparation fails, the barrier is removed and the same locks and drafts remain usable without creating a project revision.

Only a fully prepared operation reaches the Destructive Project Lock Drain. Lease invalidation, editing-surface termination, draft discard, and the prepared global mutation are finalized as one server-controlled commit transition. No new operation can enter between drain and commit. Clients retain their local draft state until the server reports successful commit; an aborted commit keeps or restores the original leases and editing state rather than treating preflight authorization as permission to lose data.

Normal server or world shutdown does not wait for this interactive flow. It releases all leases and discards all uncommitted drafts as an unavoidable connected-lifecycle exit while preserving the latest accepted authoritative project state through the normal persistence path.

On a successful archive or deletion, the commit response also closes the affected editing surfaces atomically from the server's perspective. Archived surfaces receive the last authorized document needed for Archived Inspection State and then stop receiving live project updates; deleted surfaces receive only the bounded lifecycle notice and no document payload. A failed drain or global mutation does not partially close tabs or discard their drafts.
