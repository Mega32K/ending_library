# Separate validation-probe density from Bake keyframe density

Adaptive Bake uses a finite Maximum Validation Probe Gap to bound how far apart temporary trajectory checks may be: High Precision uses `0.025s` (half a game tick), Balanced uses `0.05s` (one game tick), Draft uses `0.1s` (two game ticks), and Custom accepts a finite strictly positive server-bounded logical-time value. These defaults derive from Minecraft's 20 TPS and never from Display Frame Rate. Exact scope endpoints, source-key times, discontinuity boundaries, and deterministically known extrema remain mandatory probes even when they fall between the regular probe positions.

Validation probes are temporary computation data, not authored keyframes. A long exactly linear interval may be checked by many probes while retaining only its required endpoints. In Adaptive Error-Bounded mode, only the deterministic greatest-error failing probe is promoted to a generated keyframe before the affected interval is refined and revalidated. In Fixed Interval mode, probes measure and disclose fidelity but never add to or move the requested output grid; a Fixed-Interval Fidelity Warning therefore describes the exact candidate rather than an adaptively repaired one.

Validation Probe Count and Generated Keyframe Count use separate finite server-authoritative budgets and are reported separately in the Tool Operation Preview. Exhausting the probe or computation budget before complete validation is a hard failure for both sampling modes and cannot use `Bake Anyway`, because unknown fidelity is not equivalent to known low fidelity. Custom gap input is never clamped or silently reset, and equal authoritative inputs, scopes, profiles, gaps, and budgets must produce the same ordered probes and generated nodes.
