# Manage command-event locks as server leases

A Command Event Personal Edit Lock is acquired only when an authorized participant opens the corresponding command-event properties editor. Selecting the event, clicking a runtime diagnostic, opening a read-only inspection surface, or previewing the animation does not acquire the lock. If acquisition succeeds, the active Editing Session receives the holder identity and visible `editing` state; if another participant already holds it, the properties editor opens as a Locked Command Event Read-Only View and explains who is editing the event.

The lock is released when the holder successfully confirms the event transaction, cancels the draft, or closes the properties editor. Authoritative validation failure does not release it: the rejected draft remains local and the holder may correct and resubmit it without another participant taking the event between attempts. Switching to another Project Tab or closing the Camera Animation Editor releases the lease under the existing draft rules. A definitive Connection Lifecycle Exit and normal server or world shutdown release every affected lease and discard uncommitted command drafts. During a Transient Connection Interruption the server lease may expire normally, while the client retains command text only as a Retained Reconnect Draft and stops presenting the lease as valid.

The server owns lease validity and applies a finite heartbeat expiry so a crashed or disconnected client cannot retain an event indefinitely when an explicit release message never arrives. A live properties editor renews its lease at a bounded cadence; missed renewal causes server-side release and makes any later submission from that stale editor invalid until the player explicitly reacquires the lock against the current event revision. Reconnect Revalidation never renews or assumes the old lease automatically; it must reacquire the event explicitly and resolve any changed holder, event identity, revision, or permission state first. Lease records and heartbeat tasks are bounded by active editing participants, removed at every terminal lifecycle path, and never persisted into project content, checkpoints, animation JSON, or personal Undo/Redo history.

A valid lease cannot be transferred, stolen, or replaced by an ownership queue. Project ownership does not bypass the lease. A participant who needs the event may send a bounded Command Lock Release Request, but only the current holder's normal release actions or server-detected lease termination make the event available again.

The Editor Status Bar exposes the bounded number of active Command Event Personal Edit Locks for the current Editing Session. Opening that status item shows a read-only list of affected events, current holders, and lease condition; inspecting it never acquires, renews, releases, transfers, or requests release of a lock. Lock-release requests remain explicit actions from the relevant command-event editing surface rather than hidden status-bar mutations.
