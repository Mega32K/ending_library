# Store camera behavior fields in per-animation properties

All supported discrete camera behavior and playback fields that belong to an animation are stored in that animation's Animation Properties rather than in project-wide defaults or separate event tracks. This includes the previously identified playback mode, first-person compatibility, camera locking and freezing behavior, FOV locking, mouse control, follow-position behavior, forced camera control, available camera area, and the explicit Runtime Input Policy, together with any other verified non-numeric field that is part of the current animation contract. Numeric camera values remain in their scalar tracks, while these per-animation fields are edited as animation metadata and applied when that animation runs.

The editor exposes these settings through a Blockbench-inspired Animation Properties Popup. The popup opens from the animation item's context menu via Properties and also from a left-button double-click on the item. It edits only the current animation, uses a compact dark layout with relative and responsive placement, and treats the screenshot's other controls as visual-layout references rather than additional requested features. No screenshot-only option is added unless it is separately part of the camera animation contract. The right-side Contextual Property Inspector does not duplicate or partially edit these transactional Animation Properties.

The popup is a Property Modal Surface under ADR-0203 and inherits its shared overlay placement, focus restoration, dismissal, and responsive scrolling rules.
