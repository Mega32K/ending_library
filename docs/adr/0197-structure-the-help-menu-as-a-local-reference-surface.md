# Structure the Help menu as a local reference surface

The top toolbar exposes a Help Menu divided into Learn, Reference, Support, and About groups. Learn opens the bundled Camera Wiki, quick-start material, and context-specific help for the current target. Reference provides searchable shortcuts, camera-field definitions, command semantics, project-format and JSON compatibility notes, and the Owner/Editor collaboration rules. Support opens the bounded session-visible Runtime Diagnostic Panel, creates an explicitly requested privacy-filtered Support Summary, and reveals the verified local logs or documentation directory. About shows the EndingLibrary, camera editor, Minecraft, Forge, Project Format, and server-advertised capability information.

All Help actions are client-local and read-only. They never edit the Project Document, create revisions or checkpoints, enter personal Undo/Redo, change the playhead or playback state, start or stop a Project Runtime Instance, acquire content locks, or transmit private drafts. Bundled Markdown documentation remains available offline; external web resources are optional supplements. Contextual Help Target resolution must point to the matching Camera Wiki section when it exists, and otherwise show a truthful built-in explanation rather than a generic homepage or invented behavior.

The Help Directory Action reuses the existing client-only Directory Reveal and Native File Dialog Adapter boundaries. The implementation delegates to the verified current-platform abstraction so Windows, Linux, and macOS use their normal file-manager behavior; common and dedicated-server code must not load platform-specific APIs. If the action cannot initialize, it reports a bounded failure through the normal status surface instead of blocking the render thread or selecting a path silently.
