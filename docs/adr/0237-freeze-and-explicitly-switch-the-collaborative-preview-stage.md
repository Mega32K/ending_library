# Freeze and explicitly switch the collaborative preview stage

Starting a Collaborative Preview captures the current project Preview Stage as an immutable `Collaborative Preview Stage Snapshot`. All joined participants use that snapshot for relative-track transformation, trajectory rendering, frustums, lens visualization, and world-space camera overlays. The active preview therefore cannot jump when an editor captures or edits the live project's stage metadata.

Stage Capture and ordinary stage-property edits remain valid server-ordered project metadata operations under the normal permission, conflict, revision, persistence, and personal Undo/Redo rules. They update the live Project Document and may be visible to active editors outside the preview, but they do not mutate the active preview stage snapshot. The editor clearly indicates that a newer project stage exists without presenting it as already applied to the shared preview.

Only the Preview Leader may invoke `Preview Stage Switch`. The server validates the selected project stage, preview-session generation, participant set, dimension availability, and resource limits, then pauses the shared preview at one authoritative logical time, applies the new stage snapshot to every joined participant, preserves the current logical playhead and work range, and resumes using one deterministic synchronized transition only if the preview was playing before the switch. A paused preview remains paused; no switch resets time, restarts from zero, or silently changes the work range. A stale, invalid, or unavailable stage rejects the complete switch and leaves the current preview unchanged. Followers cannot request or apply the switch, and no stage operation teleports players, changes gameplay cameras, alters runtime instances, or creates a second hidden preview.

Stage-switch packets are idempotent and generation-bound. Delayed ordinary stage edits, duplicate switch results, or messages from a terminated preview cannot replace the active snapshot. Ending the preview releases the stage snapshot with the rest of the bounded collaborative-preview resources; the persisted project stage remains governed by the Project Document and is not rolled back by preview restoration.
