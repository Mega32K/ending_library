# Let the server order collaborative edit operations

Participants may edit the same camera animation without acquiring an exclusive document lock. Clients submit fine-grained edit operations against an expected revision together with an Operation Footprint describing the stable fields and structures they touch. The server validates the operation and its declared resource usage against the centralized Collaboration Resource Budget, compares a stale operation's footprint with accepted changes since its baseline, and serializes it only when the touched paths are safely disjoint. Non-overlapping fields may be semantically rebased onto the current document; the client never silently retries against a new baseline. Accepted operations increment the authoritative revision and are broadcast to every participant. Budgets are intentionally generous for large animations and multi-user sessions, but remain finite and server-authoritative. Presence state remains local or ephemeral, and undo is represented by compensating a participant's accepted operations rather than replacing the whole animation with an older client snapshot.
