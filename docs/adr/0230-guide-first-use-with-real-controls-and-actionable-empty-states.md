# Guide first use with real controls and actionable empty states

When the Camera Animation Editor opens without a Project Tab, it presents the complete Project Browser workspace rather than an empty editor shell. Its primary empty-state actions are `Create Project`, `Open Project`, and `Import Animation`, each with concise localized guidance. No project, server record, animation, checkpoint, runtime instance, or preview is created until the player explicitly invokes and confirms an applicable action.

The first editor use offers one optional, skippable `First-Use Editor Tour`. The tour points to the actual responsive controls that currently exist for the Project Workspace Bar, Project Browser, Live World Viewport, animation resource area, Camera Track Tree, Timeline or Graph Editor, Property Inspector, Local Preview, Collaborative Preview, and Runtime Publication. If the layout has moved a surface into a drawer, overflow menu, or compact entry point, the tour resolves that current entry instead of using fixed screen coordinates or pointing to hidden UI. The tour never edits content, creates a project, starts playback, publishes, enables runtime animation, changes selection, or takes over the player's camera.

Tour completion or dismissal is stored only as a device-local Global Editor Preference. The Help Menu provides `Replay Editor Tour`, which restarts the walkthrough without resetting other preferences or changing project state. The tour remains fully keyboard navigable, narrated under the Editor Accessibility Contract, localized under the Editor Localization Contract, and compatible with Reduce UI Motion.

Every empty editor surface follows the `Actionable Editor Empty State` rule. A panel, result list, track view, search result, permission-limited view, disconnected state, or validation surface explains why content is absent and offers only valid recovery or creation actions. A decorative image or icon may support the message but can never be the only content or replace a usable next step.
