# Run validation as cancellable background checks

Validation runs as a bounded, read-only background task rather than on the editor input or rendering path. Starting a run captures the selected `Validation Scope` and the current authoritative project, Project Tab, animation/focus, and accepted-revision identity. The task reports meaningful phases such as collecting targets, checking timing and curves, checking runtime compatibility, and checking resource budgets without blocking editing, playback, selection, collaboration, or ordinary UI navigation.

The validation surface exposes an explicit Cancel action while a run is pending. Cancellation is cooperative before the task reaches its terminal-state publication; it releases the task's bounded temporary state and produces a cancelled status without changing project content, runtime state, personal history, or the last completed report. Closing the tab, changing the relevant animation or scope, leaving the connection/world lifecycle, or replacing the authoritative context invalidates the task and cancels or supersedes it. A late result is discarded when its connection, project, tab, scope, context, or accepted-revision identity no longer matches the active request.

The UI displays the current phase and truthful terminal status, but does not show a fabricated percentage or per-item progress stream. A new run is single-flight for its active editor context: an explicit replacement cancels or supersedes the previous run instead of queueing work or retrying automatically. Only a valid terminal result may replace the displayed Validation Report; stale, cancelled, unavailable, or failed results cannot overwrite a newer report, and a failed or cancelled explicit rerun leaves the prior Outdated Validation Report available. Validation remains read-only and never creates a project revision or Undo/Redo entry.

A successful run preserves complete aggregate counters while retaining only the Validation Finding details permitted by the Validation Detail Budget; reaching that detail budget yields a truthful Details-Limited Validation Report rather than cancellation or partial-success ambiguity. A run cancelled, invalidated, or stopped by its deadline still publishes no new report or partial totals.

This keeps expensive whole-project checks responsive and observable while bounding worker, queue, correlation, and diagnostic state across normal editor and connection lifecycles.
