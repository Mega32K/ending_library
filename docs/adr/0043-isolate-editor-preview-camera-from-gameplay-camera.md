# Isolate editor preview camera from gameplay camera

The Camera Animation Editor renders its normal preview through an Embedded Preview Viewport owned by the editor; the viewport presents the current client game scene as a centered, aspect-preserving Game Frame Preview whose view is driven only by the editor-local preview camera. The preview camera evaluates the selected project revision against the selected Preview Stage, draws trajectories and overlays, and accepts local orbit, pan, follow, lens, and playback controls. These controls never move the player, change the active gameplay camera entity, mutate camera Capability values, or send a gameplay camera command to the server.

Immersive Preview is an explicit local presentation mode, not the default editing path. Before entering it, the client captures a Camera Restoration Snapshot containing the current camera entity, position and rotation, FOV and related lens state, input focus, mouse capture/visibility state, and any editor-to-gameplay routing flags. The preview renderer may then drive the local render camera only for that participant. Collaborative Preview synchronization does not implicitly enter Immersive Preview for anyone.

Leaving Immersive Preview restores the snapshot before normal editor input resumes. Restoration is attempted on ordinary exit, `Esc`, editor close, connection loss, world change, dimension failure, render failure, and other client-side exceptional paths. Preview Availability State remains visible during restoration and reports any degraded fallback rather than implying that ordinary editor or gameplay camera ownership has already resumed. If a restoration field is no longer valid, the client uses the safest verified Minecraft client fallback and exposes the degraded state; it never leaves the editor preview camera attached silently. The restoration snapshot is temporary workspace state and is not persisted in the Project Document, Project Snapshot, Operation Journal, Presence, or server runtime state.

The editor must keep preview-camera ownership explicit in its rendering and input layers so an embedded viewport cannot accidentally call gameplay camera mutation APIs. Any future action that publishes or applies an animation to gameplay is a separate server-authorized runtime operation outside the editor preview lifecycle.
