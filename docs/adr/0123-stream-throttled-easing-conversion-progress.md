# Stream throttled Easing conversion progress

The editor receives bounded, throttled status updates for an Easing-to-Bézier conversion request rather than one network message per sample or generated node. The visible phases are queued, computing, validating, committing, and a terminal result. Computing progress may report the active source interval, generated-node count, sample count, current maximum error, selected target, and budget proximity; percentage remains explicitly indeterminate when the adaptive algorithm cannot estimate completion reliably. Intermediate candidates are never project content and are never sent as partial node lists. A completed task sends one authoritative result and diagnostics, while cancellation, timeout, rejection, and failure send only their terminal reason.
