# Bound validation details without losing total counts

A successfully completed Cancellable Validation Run scans its complete validated target and keeps exact aggregate counts, but retained focusable Validation Finding details are constrained by one server-authoritative Validation Detail Budget with generous finite limits overall, per Validation Severity, and per stable diagnostic code. Retention follows deterministic canonical project order and reserves independent severity capacity so large Warning or Information sets cannot consume all Error detail capacity; concrete defaults are chosen through implementation load testing and remain server-configurable only within hard ceilings.

Reaching the detail budget produces a successful Details-Limited Validation Report rather than a failed run or silent truncation. The report shows `Details Limited` and the total-versus-retained count for every affected group, while search and filters truthfully state that they cover only retained details; it offers an explicit narrower-scope rerun such as the affected animation, but no unlimited Load More, automatic retry, or permanent full-result archive. Existing cancellation, deadline, and lifecycle rules still prevent an incomplete scan from publishing partial totals as a successful report.
