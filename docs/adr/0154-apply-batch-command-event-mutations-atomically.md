# Apply batch command-event mutations atomically

Batch mutations over selected Command Animation Effect Events use a server-authoritative all-or-nothing transaction. Before changing any event, the server verifies the participant's role, expected project revision, stable identities, current event contents, resource limits, and every selected event's personal-lock state. A lock held by another participant blocks the complete mutation; the server never silently skips locked items, allows the Project Owner to bypass a valid lease, or exposes a partial result as success. Read-only selection, copy, preview, and diagnostics remain available for locked events.

A successful batch applies all selected mutations together, creates one authoritative project revision, and records one personal Undo/Redo item. Copy creates a Structured Editor Clipboard payload from accepted event content without requesting a lock. Duplicate and Paste first create local Paste Preview Drafts and do not become shared content until their own authoritative confirmation succeeds. Rejected preflight leaves all selected events and local drafts unchanged while reporting the blocking condition in a locatable, non-destructive way.
