# Allow explicit low-fidelity Fixed Interval Bake

Fixed Interval Bake treats the requested interval as an exact sampling contract: it generates that grid together with mandatory scope endpoints, source key times, and discontinuity boundaries, but never inserts undisclosed adaptive samples merely to improve fidelity. The candidate is still measured against the recommended unit-aware trajectory threshold. Exceeding it produces a `Fixed-Interval Fidelity Warning`, not an automatic mode change or a silent interval reduction.

The Tool Operation Preview identifies every affected Scalar Animation Track and Additive Lane, the maximum error and its Timeline Time, and the existing graph/world comparison. Its preferred recovery actions are to reduce the interval or explicitly recompute in Adaptive Error-Bounded mode. The user may instead choose the secondary `Bake Anyway` action, which opens one Blocking Transaction Surface with cancellation focused, explains the measured deviation, and has no permanent or remembered warning bypass.

Only a finite, otherwise valid, resource-compliant Fixed Interval candidate may use this warning path. Non-finite evaluation, invalid time or duplicate structure, failure to preserve an outside trajectory, stale authoritative state, payload or node limits, and other hard validation failures continue to block confirmation. Adaptive Error-Bounded Bake also remains strict: failure to satisfy its selected fidelity target cannot be acknowledged away. An accepted fixed candidate still commits atomically as one project revision and one personal Undo/Redo item without changing its interval, mode, or disclosed node set.
