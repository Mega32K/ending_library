# Delay explanatory tooltips for camera editor buttons

Every actionable button in the Camera Animation Editor uses a shared Camera Editor Button Tooltip contract. If the mouse pointer remains over the same button for more than one second, or keyboard/controller focus remains on the same button for more than one second, the client renders a concise explanation beside that button. The tooltip describes the button's purpose and relevant scope or consequence, but never executes the action, changes selection, opens a preview, or creates network or project state. The same contract applies to disabled buttons through a hoverable or focusable non-activation surface; a Disabled Button Tooltip adds the current blocking reason while preserving the disabled state.

The tooltip is positioned by the responsive layout system rather than fixed Minecraft screen coordinates. It prefers the side adjacent to the button, avoids covering the button or the active modal's critical controls, clamps within the available viewport, and does not reflow or resize the underlying editor. Only one delayed tooltip is visible for the current interaction context. Moving away, entering another button, changing keyboard/controller focus, closing the containing surface, or losing the relevant UI context cancels the pending or visible tooltip. Pointer hover and non-pointer focus share the same content, delay, replacement, and cancellation rules.

The contract applies to toolbar buttons, File and Settings controls rendered as buttons, panel and popup action buttons, project-browser buttons, timeline-toolbar buttons, and other camera-editor buttons. It does not add automatic hover surfaces to timeline nodes, curves, labels, text fields, numeric inputs, selection outlines, or ordinary decorative elements merely because they are interactive or visually selectable. Those surfaces retain their separately defined interaction and validation feedback.

Tooltip text is short, truthful, localized through the editor's normal text system, and semantically distinct from error, conflict, or status messages. Rendering a tooltip is client-local and ephemeral: it is never persisted, synchronized, journaled, or included in Undo/Redo.
