# Run keyframe reduction as bounded single-flight work

Remove Redundant Keyframes runs outside the game render and server tick paths as a Bounded Key-Reduction Run. A responsive client Tool Operation Preview uses a camera-editor-owned worker with finite concurrency and queue capacity. Each Project Tab has at most one active reduction preview: changing its scope, tracks, fidelity, or other relevant input cancels or supersedes the old generation, and only the latest complete generation may replace the visible preview. The global client worker remains bounded even when several Project Tabs exist.

Confirmation never trusts the client's proposed deletion set. The server captures a bounded immutable numeric snapshot from the declared authoritative baseline and deterministically recalculates the complete result on a camera-editor-owned bounded worker. At most one confirmation task exists for the same player and project, repeated confirmation cannot create a duplicate queue, and task data never retains player entities, worlds, dimensions, screens, or other lifecycle-heavy objects.

Both preview and confirmation enforce finite candidate-count, evaluation-count, snapshot-size, queue-wait, and active-computation budgets. Cancellation, a relevant accepted project edit, stale identity, tool or Project Tab exit, connection or world lifecycle exit, timeout, or budget exhaustion releases the snapshot and task handle and produces no partial candidate, automatic retry, silent scope reduction, or relaxed fidelity. UI progress is throttled to truthful phases and bounded aggregate counts; intermediate deletion sets are not confirmable.

The server-thread terminal gate gives a confirmation exactly one outcome. Before atomic commit, cancellation or invalidation discards the completed or partial calculation; once atomic commit begins, the complete verified edit finishes without partial rollback and creates one project revision plus one personal Undo/Redo item. Late callbacks and superseded generations cannot mutate project or UI state.
