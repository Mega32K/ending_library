# Bind per-channel camera JSON through explicit modifier context

The native camera-animation Project Document contains all supported `ModifierType` scalar tracks in one collaborative project. Both Extended Camera Animation JSON and the Legacy Animation Format remain per-animation documents whose fields describe the animation name, playback type, duration, grouped keyframes, easing fallback, and—only in the extended profile—optional custom curve segments. Neither profile identifies which camera value it modifies. The converter therefore treats modifier ownership as import/export context, not as an inferred payload property.

When importing one camera-animation JSON file, the editor uses the currently selected scalar track only when that selection is unambiguous. With no compatible track selected, it asks the user to choose the target `ModifierType`. The import preview displays the source profile, destination track, lane mapping, curve compatibility, and warnings before any project mutation. A malformed or unsupported target cancels the import rather than assigning the file to a default channel silently.

When importing a camera-animation directory, the converter recognizes a verified `ModifierType` directory name and applies every valid file below it to that channel, preserving each file's animation name, group lanes, and supported curve data. Unknown or ambiguous directory names require explicit mapping. A batch import validates all files, destinations, resource budgets, format versions, and conversion warnings before submitting one atomic project operation or a clearly segmented set of operations; it never partially imports an unreported subset.

Exporting one selected scalar track offers Extended Camera Animation JSON as the lossless current profile and Legacy Animation Format as the explicit older-reader compatibility profile. Exporting all tracks creates a directory structure grouped by `ModifierType`, matching the existing resource/export convention. The native Project Document remains the lossless format for cross-channel metadata, stable identities, collaboration data, and editor extensions. Neither JSON profile gains a `modifierType` field, because channel ownership remains explicit external context rather than duplicated payload state.
