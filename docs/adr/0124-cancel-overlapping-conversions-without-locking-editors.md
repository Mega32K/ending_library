# Cancel overlapping conversions without locking editors

Running Easing-to-Bézier conversion tasks do not lock their source nodes, tracks, project, or editing session. Other authorized participants may continue submitting ordinary edits. Each task registers a lightweight logical conversion footprint: disjoint accepted operations leave the task running, while an accepted operation that changes a source node, Easing mode, timestamp, value, existence, ordering, interval adjacency, or relevant track structure immediately marks the task stale and requests cooperative cancellation. The collaborator's edit is never delayed or rejected merely because conversion computation is active. The requester keeps the conversion window open, receives the changed authoritative range, and must inspect and explicitly confirm a newly generated preview. Commit-time semantic validation and the terminal-state gate remain the final race-condition safeguards.
