# Make transform write targets explicit in the 3D editor

Dragging a camera result in the 3D viewport never infers whether the user intended world translation or camera-relative translation from the drag vector or final position. The editor maintains a Transform Write Target, selected by the active track/keyframe family, an explicit inspector or viewport command, or the player's last project-scoped target when no conflicting selection exists. The editor does not attach a text label, `T`/`R` badge, or mode panel to the gizmo; selected tracks, trajectory contributions, handle treatment, and conflict rendering communicate the binding primarily through the scene itself.

Gizmo Orientation is independent from the write target. A user may write to world translation while viewing world, Preview Stage, or camera-local axes, or write to camera-relative translation while using another visual basis. Selecting a `TRANSLATION_*` family binds Translation; selecting a `RELATIVE_*` family binds Relative; an explicit viewport command overrides inferred selection. If a selection contains both families or no safe target, the editor enters Binding Conflict, blocks the drag, and requires the user to choose Translation or Relative before starting the gesture.

Auto Key creates or updates keys only in the resolved target family. A target change during an active drag cancels the preview and requires a new gesture. The complete drag, including track creation, key insertion/update, duration extension, and linked-axis changes, is one Edit Gesture Transaction and one personal Undo/Redo unit. The viewport preview shows the pre-edit result, the in-progress result, and the target contribution without changing player position or capability runtime state.
