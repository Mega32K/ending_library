# Bind explicit permission rejoin to one authoritative baseline

`Explicit Permission Rejoin` is one server-authoritative transaction that binds permission validation, project lifecycle and format validation, the loaded Project Document, and the new Editing Session to a single `Atomic Rejoin Baseline`. The tab remains read-only throughout the request and cannot submit edits, execute Undo/Redo, acquire locks, or broadcast Presence. If collaborators modify the project while the request is being prepared, the server completes the rejoin from a current stable authoritative revision rather than the frozen client view or an earlier partially loaded snapshot. Only after the baseline and document are accepted does the client enter ordinary editing or the ADR-0207 draft-review gate; retained material is never merged automatically.
