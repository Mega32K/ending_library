# Edit curve boundaries precisely in the inspector

Selecting a Curve Segment links the Curve Segment Inspector section of the right-side Contextual Property Inspector to that exact segment. The fixed Inspector Target Header identifies the owning animation, track, and selected segment. The inspector first shows its Curve Interpolation Mode. When the mode is `BEZIER`, it then renders separate Start Boundary and End Boundary sections rather than merging both handles into one ambiguous control group.

Each boundary section provides a segmented `AUTO`, `ALIGNED`, `MIRRORED`, and `BROKEN` Tangent Mode selector plus precise fields for the handle owned by the selected segment. Time is a forward-only percentage of the selected segment; Value uses the owning track's actual authored unit and may overshoot the boundary keyframe values. If the current mode couples the opposite handle in the preceding or following Curve Segment, the section visibly identifies that adjacent segment and states that the confirmed edit affects it as well. The inspector preview, graph handles, curve geometry, and affected-neighbor indication remain synchronized.

`AUTO` handle coordinates are displayed read-only. Beginning a direct numeric coordinate edit is an intentional manual-authoring request: the editor freezes the current computed positions, promotes that boundary to `ALIGNED`, and applies the entered value without an initial visual jump. The promotion and confirmed numeric edit form one atomic project transaction and one Undo/Redo entry. An explicit mode switch is likewise one authored operation. Invalid input, cancellation, or server rejection restores the complete prior mode and handle state.

`LINEAR` and `CONSTANT` hide Bézier boundary-coordinate controls. `EASING_PRESET` exposes its preset choice rather than inactive handle fields. The inspector does not reveal graph handles merely because it is open; handle visibility continues to require an explicitly selected Curve Segment in Graph Editor Mode.
Numeric-field editing uses a local preview until confirmation. `Enter` confirms the current field, focus loss confirms it, and `Esc` restores the value captured when field editing began. The physical numeric-keypad Left gesture confirms a valid current field and focuses the previous ordered curve field; the physical numeric-keypad Right gesture confirms it and focuses the next. Depending on NumLock, these are the keypad Left/Right keys or Numpad 4/Numpad 6. Main-keyboard left and right arrows continue to move the text caret and never switch fields. `Tab` retains general UI focus navigation rather than serving as the dedicated curve-field traversal gesture. Invalid, empty, non-finite, malformed, or out-of-range input keeps focus in the current field, renders a visible error, blocks keypad traversal, and creates no project transaction.
