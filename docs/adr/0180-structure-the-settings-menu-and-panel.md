# Structure the Settings Menu and responsive Settings Panel

The top toolbar exposes a Blockbench-style Settings Menu for player-local Global Editor Preferences. The menu groups quick controls and links to the responsive, dockable Settings Panel. The initial categories are Interface, Timeline, World Viewport, Input and Shortcuts, Collaboration Display, and Performance and Preview. Interface includes the Standard Dark and High-Contrast Dark Editor Theme Profiles plus the Compact, Standard, and Comfortable Editor Density Profiles. World Viewport includes the Default View Layer Profile and Promote Current View Defaults action. The category names are stable UI entry points, while individual settings may be added only when their scope and persistence boundary are defined.

Simple booleans and bounded selectors apply immediately to the local client presentation or interaction model. Complex settings open the Settings Panel with the relevant category focused. The panel is responsive and relative-layout based: it uses available content bounds, minimum hit targets, bounded typography, scrollable content, and collapsible category navigation rather than Minecraft's original absolute coordinates. Narrow layouts preserve the active settings content and move navigation into a drawer or compact tab strip. There is no global Apply or Cancel action; settings that require reopening the editor or reloading a client resource report that boundary explicitly.

The Settings Panel provides search over setting titles, descriptions, and category names; search results are local metadata only and are not sent to the server. Each category has a local reset action, and a full reset action restores all Global Editor Preferences only after explicit confirmation. Resetting settings never changes Project Document content, Authoritative Revision, personal Undo/Redo, Project Workspace Layout snapshots, runtime publication, or camera playback.

Global Editor Preferences are persisted in the client-local Device Preference Store and therefore survive game restart, project changes, and server changes. The panel must show that scope in its help text or category headers. Project Workspace Layout, open-project tabs, playhead, selection, local drafts, collaborator presence, and runtime playback are not stored there.

Settings controls follow the shared tooltip contract for buttons, including delayed explanations for disabled controls. Every advertised setting must have a real state binding, validation, immediate feedback, and a defined persistence boundary; placeholder controls and visual-only settings are not permitted. The Settings Menu and Panel close without changing the active project, selection, playhead, viewport observation state, or collaboration presence.
