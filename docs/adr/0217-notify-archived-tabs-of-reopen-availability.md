# Notify archived tabs of reopen availability

When an archived project is restored, the server sends one bounded `Archived Reopen Availability Update` to each still-open `Archived Inspection State` tab for that project. The client updates the tab's lifecycle status, enables `Reopen Project`, and may show the independent `Archived Reopen Indicator` when the tab is not active, but does not load a new Project Document, recreate an Editing Session, reacquire Presence or locks, apply drafts, restore playback, or start runtime animation. The notification follows the `Non-Interrupting Lifecycle Notice` rule: it never steals focus, opens a blocking surface, changes selection or workspace placement, pauses local inspection playback, or replaces the held inspection document. If the affected tab is active, one short-lived status notice may identify that reopening is now available. The notification is a status change, not an implicit rejoin.

The update is idempotent and contains only the project identity, lifecycle outcome, and the availability state needed by the tab. It has no unbounded retry or retained document payload. If delivery is missed, delayed, duplicated, or received after the tab has closed, the result is harmless; focusing the tab or opening the Project Browser performs an explicit lifecycle-status revalidation. A deletion or another lifecycle transition supersedes the availability state and moves the tab through the existing Deleted Project Notice or other authoritative outcome.

If the project is archived again before the player invokes `Reopen Project`, the later authoritative archive outcome immediately disables the action and clears the `Archived Reopen Indicator`. The tab remains in `Archived Inspection State`, retains its already-held inspection document, and does not show a blocking confirmation or interrupt isolated local inspection. If the later outcome is deletion, the tab instead enters `Deleted Project Notice` and no longer exposes the held project content.

This push-plus-focus-revalidation model avoids high-frequency polling while keeping the visible tab responsive. The user must still deliberately invoke `Reopen Project`, which performs the complete `Explicit Permission Rejoin` flow against a new `Atomic Rejoin Baseline`.
