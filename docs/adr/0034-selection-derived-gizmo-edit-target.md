# Derive the gizmo edit target from keyframe selection

The 3D gizmo has two editing meanings but no separate mode button or shortcut. When one or more keyframe nodes are selected, a gizmo gesture edits the compatible selected keyframes. When no keyframe node is selected, the gesture edits the evaluated camera pose at the current playhead time. Selecting or deselecting nodes therefore switches the edit target implicitly, while the target resolved at gesture start remains fixed until that gesture ends or is cancelled.

In playhead-targeted editing, enabled Auto Key creates or updates the required keyframes at the playhead, including any necessary track creation and duration extension, as one Edit Gesture Transaction. With Auto Key disabled, dragging produces only a Ghost Transform Preview and does not mutate the project until the user explicitly confirms an authoring operation. In selected-keyframe editing, the gesture modifies only compatible authored channels represented by the selection; incompatible handles are disabled rather than silently redirecting the edit to the playhead.

The viewport does not place an editing-target label, badge, explanatory panel, or explicit target-mode control beside the gizmo or in the Viewport Control Bar. It communicates the current meaning through visual state: selected keyframe and trajectory-node emphasis, the visible playhead sample when no node is selected, handle availability, ghost-versus-authored rendering, and linked timeline selection. These states use shape, outline, opacity, and motion treatment in addition to the Blockbench-inspired blue selection color so the interaction remains readable without relying on text or color alone.
