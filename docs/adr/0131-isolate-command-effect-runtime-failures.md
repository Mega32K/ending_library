# Isolate command effect runtime failures

Command Animation Effect Events are validated for syntax and the configured Command Effect Permission Policy before executable project content is published, but runtime conditions may still make a command fail. Such a failure affects only that event crossing: it does not pause or stop the Project Runtime Instance, roll back already executed same-time events, skip later events, or create an automatic retry. Remaining events at the timestamp continue in Same-Time Effect Order, and a later `LOOP` playback pass may attempt the command again as a new crossing. If the runtime target player or instance is no longer valid, the event is cancelled rather than substituting another command source. The Silent Command Runtime Source remains silent, while the server records only bounded and throttled diagnostics so a repeatedly failing loop cannot create unbounded logs or retained failure state.
