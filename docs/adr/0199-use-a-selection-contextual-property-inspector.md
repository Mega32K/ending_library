# Use a selection-contextual right-side property inspector

The Camera Animation Editor uses a Blockbench-inspired Contextual Property Inspector as its ordinary right-side authoring surface. A fixed Inspector Target Header identifies the current target count, semantic type, name, owning animation, and editable, read-only, or lock state. Below it, compact collapsible sections place labels on the left and controls with visible units on the right, support scrolling without moving the header, and omit persistent hover action strips or decorative controls. No selection produces a concise selection guide rather than duplicating Animation Properties or inventing project-wide values.

A single numeric keyframe exposes time, Authored Value, Evaluated Value, Curve Interpolation Mode, and the applicable easing or Bézier controls. Compatible same-type multi-selection exposes shared fields with Mixed Inspector Value where accepted values differ; committing one shared field is one atomic Inspector Batch Edit. A heterogeneous selection exposes only fields with identical semantic meaning, unit, validation, and mutation behavior. Track, Project Timeline Marker, and explicitly selected Curve Segment targets receive their own focused sections. A selected Command Animation Effect Event shows only its accepted summary and an explicit action that opens the established lock-aware properties surface; command text is never edited inline in the inspector. Animation metadata remains in the separate transactional Animation Properties Popup.

Ordinary inspector fields do not use a panel-wide Confirm or Cancel transaction. Text or numeric input remains a local field draft until a valid Enter or focus-loss commit; Escape restores the value captured when that field edit began. Invalid, empty, malformed, non-finite, out-of-range, stale, conflicted, or server-rejected input remains visibly explained and creates no project mutation. Every accepted single-target or batch field commit follows the existing server validation, collaboration ordering, Auto Key, overwrite confirmation, duration linkage, and personal Undo/Redo contracts.

The inspector is an auxiliary panel under the existing docking rules. It may be docked, tabbed, floated inside the Workspace Shell, hidden, or restored, and becomes a real right-side drawer before it can reduce the Live World Viewport or Timeline Panel below their Minimum Usable Region. Its local section expansion, scroll, and focus state follow Project Workspace Layout lifecycle rules. Buttons inherit the delayed camera-editor tooltip contract, while ordinary numeric fields rely on persistent labels, units, validation text, and accessible descriptions rather than forced hover tooltips.
