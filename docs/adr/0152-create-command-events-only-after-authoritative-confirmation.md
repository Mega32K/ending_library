# Create command events only after authoritative confirmation

Starting a new Command Animation Effect Event creates only a private client-local Command Event Creation Draft with a temporary local identity. It is not broadcast, persisted, assigned a stable event identity, represented by a server event, protected by an event lock, or added to project revision and Undo/Redo history while it remains a draft; cancellation, properties-editor closure, project switching, editor closure, or connected-lifecycle exit discards it completely.

Confirmation is one server-authoritative atomic creation transaction. The server validates the normalized command, authored time, Same-Time Effect Order, resource limits, expected project revision, and any same-type occupancy conflict before assigning a stable event identity and creating the shared event, one authoritative revision, and one personal Undo/Redo item together. Validation or conflict failure leaves the local draft and properties editor available for correction while the accepted project remains unchanged. A creation lock is unnecessary because no shared event exists before this commit gate; concurrent creation conflicts are resolved by the same authoritative transaction rather than by publishing provisional empty events.
