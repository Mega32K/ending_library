# Preserve editor workspace state only within one connected lifecycle

When a player explicitly closes the current Camera Animation Editor page, the connected editing context records that player's workspace state for the current project. The snapshot includes the last opened editor location, Current Edited Animation, and playback time, and may include animation-keyed non-content navigation state such as the Animation Timeline View State, timeline scroll or zoom, track-tree expansion, and the Left Animation Navigation Stack splitter. Reopening the project during the same connected server lifecycle restores that snapshot.

This state is not part of the Project Document, Project Catalog, animation JSON, or durable player capability. A Transient Connection Interruption retains it only inside the same bounded connected lifecycle while the editor is in Reconnecting Read-Only State. Leaving the world or server, explicitly disconnecting, cancelling or exhausting reconnection, or otherwise reaching Connection Lifecycle Exit clears the snapshot. Accepted animation edits remain authoritative and durable; only the player's UI workspace state is discarded. The editor must distinguish explicit close, transient interruption, and definitive lifecycle teardown so normal navigation and short recovery do not make state survive a future connection.

Workspace snapshots are keyed by the pair of player identity and project identity. Closing project A and opening project B saves A's snapshot and loads only B's snapshot; no viewport, playhead, selection, or navigation state crosses project boundaries, and the snapshots are not broadcast to other participants.
