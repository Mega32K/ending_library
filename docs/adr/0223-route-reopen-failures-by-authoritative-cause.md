# Route reopen failures by authoritative cause

`Explicit Permission Rejoin` failures are mapped to a semantic `Reopen Failure Outcome` instead of one generic error with an unconditional retry button. If the project is currently archived, the tab returns to `Archived Inspection State` and disables `Reopen Project`. If it was deleted, the tab enters `Deleted Project Notice` and removes project content. If the player no longer has Owner or Editor access, the tab enters `Permission-Revoked Inspection State` and follows its frozen last-authorized-view contract.

A transient connection failure, timeout, or bounded server-capacity rejection leaves the already-held inspection content visible and preserves reopen eligibility when the latest known lifecycle state still permits it. The tab shows an inline reason and an explicit manual retry action governed by the `Bounded Reopen Retry Gate`; it does not retry in the background, create a click queue or notification queue, or claim that a session exists. A supported older format routes to the existing `Older-Format Read-Only State` and `Project Migration Prompt` path, while a newer unsupported format routes to `Newer-Format Read-Only State` and its compatibility diagnostics. Neither format outcome silently migrates, downgrades, publishes, or enables editing.

Except for deletion, a failed request preserves the client inspection content already allowed by the resulting state. Every failure releases bounded request state, creates no Editing Session, acquires no Presence or locks, changes no runtime or playback state, and adds no personal Undo/Redo entry. A later manual retry starts a new request generation and repeats all current permission, lifecycle, format, and baseline validation rather than resuming the failed request.
