# Offer explicit reopen from archived inspection tabs

An `Archived Inspection State` tab always exposes a clearly labeled `Reopen Project` action. While the project remains archived, the action is visibly disabled and explains that restoration is required; it never opens a request or attempts to bypass the lifecycle state. The server sends a bounded lifecycle notification when restoration makes the action eligible, and the client updates only the tab's lifecycle status and action availability. The notification does not load new content, join a session, or restore playback; if it is missed, focus on the tab or Project Browser triggers an explicit status revalidation. After restoration, the action becomes available without automatically loading new content or joining a session. It reuses the existing tab as a user-interface container, but it does not revive the released Editing Session, Presence, locks, subscriptions, drafts, runtime instance, playback state, or personal history. It performs the complete `Explicit Permission Rejoin` flow against the current project state and creates a new `Atomic Rejoin Baseline` before the tab can become editable again.

The rejoin replaces the inspection content with the freshly authorized Project Document only after permission, project identity, format, and baseline validation succeed. It creates a new Editing Session and new personal history segment, restores only still-valid workspace and content identities, and never auto-starts playback or runtime animation. Failure uses a semantic `Reopen Failure Outcome` rather than one generic retry state: a current archive returns to Archived Inspection State, deletion enters Deleted Project Notice, permission loss enters Permission-Revoked Inspection State, transient transport or server-capacity failure preserves the inspection view and reopen eligibility with an inline manual retry, and format incompatibility exposes the applicable read-only format or migration path. No failure reopens the old session or creates personal history.

After invocation, the tab enters a read-only `Cancellable Reopen Request`. The player may cancel or close the tab before the server reaches the atomic rejoin commit boundary. Cancellation releases the request without creating a session, changing content, or adding history and returns an open tab to Archived Inspection State. Once atomic commit has begun, cancellation no longer interrupts the transaction; late results are still gated by request and tab identity so they cannot recreate a closed tab or revive an obsolete session.

This explicit action is preferred over silently reopening from the Project Browser because it preserves the user's visible location while making the lifecycle boundary clear. It remains a deliberate rejoin, not an automatic restore or a shortcut around authorization.
