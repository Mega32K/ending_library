# Keep continuous gestures transient until release

Continuous pointer gestures are interaction previews, not a stream of project edits. At pointer-down, the client records the selected target identities, the current project revision, the relevant authored values, and the resolved Gizmo Edit Target as a Gesture Baseline. During movement it evaluates the proposed result locally and may broadcast a throttled ephemeral Gesture Preview through Collaborator Presence so other participants can see intent without observing a sequence of authoritative revisions.

At pointer-up, the client converts the complete delta from the baseline into one validated Edit Gesture Transaction with an Operation Footprint. The server checks the expected revision, permissions, target identities, field constraints, and conflict conditions before applying it atomically. If the baseline is stale but the footprint is proven disjoint from intervening edits, the server may semantically rebase the transaction onto the current document; this is an explicit server decision, not a client-side silent retry. If accepted, the transaction receives one authoritative revision, is appended as one Operation Journal entry, is broadcast as one content update, and becomes one Undo/Redo unit. If an overlapping or structural conflict is found, the client removes the preview, retains the current authoritative state, and presents the conflict or validation reason.

The same boundary applies to multi-keyframe drags, trajectory edits, curve-handle drags, range changes that alter authored data, and numeric fields confirmed by Enter or focus loss. Timeline scrubbing and viewport observation remain non-authoring local state unless an explicit authoring command converts them into an Edit Gesture Transaction. A cancelled gesture, `Esc`, an explicit revert-to-baseline action, or connection loss removes only transient preview state; it does not create a revision, journal entry, or undo item.

Connection interruption follows ADR-0206: the active continuous gesture is cancelled because it has no safe commit boundary, while the surrounding workspace and eligible non-gesture drafts may remain in Reconnecting Read-Only State until revalidation or lifecycle exit.

Presence previews are throttled, bounded, replaceable by the sender's newest preview, and expired when the gesture ends or the participant leaves. Their intended limits are generous enough for large multi-keyframe gestures, but remain finite and independently configurable for participant count, preview count, target count, update frequency, and serialized payload size. They must not be persisted in the Project Document, Project Snapshot, Operation Journal, Project Catalog, or durable revision history.
