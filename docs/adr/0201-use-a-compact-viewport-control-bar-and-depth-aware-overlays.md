# Use a compact viewport control bar and depth-aware world overlays

The viewport and its control bar are protected by the Core Editor Region rule. When bounds become narrow, lower-frequency controls move to the existing overflow path described by ADR-0205 instead of shrinking the world frame or its interaction targets.

The central Embedded Preview Viewport uses a dark charcoal container and centers the Game Frame Preview with its original aspect ratio. Bounded dark margins or letterboxing absorb unused space; the editor never stretches the scene or crops important camera content merely to fill the panel. A compact, near-opaque Viewport Control Bar occupies its own strip above the rendered frame rather than covering the scene. Its left side shows Preview Availability State and the live dimension or truthful fallback reason, while its right side exposes reset observation view, follow animated camera, trajectory, world-space node, camera-frustum, guide, collaborator-marker, Gizmo, Preview Stage axis, and Immersive Preview actions. Narrow layouts move lower-frequency actions into one accessible overflow menu instead of uniformly shrinking the controls.

The control bar and View Menu are two entry points into the same client-local state. Every layer button reflects and changes the current Project View State, has an accessible selected or disabled state, and inherits the greater-than-one-second camera-editor tooltip contract. No action exists only as decoration. The control bar never adds an explicit selected-keyframe-versus-playhead edit-target switch or shortcut, and it never places edit-target text beside the Gizmo; Gizmo Edit Target continues to derive implicitly from keyframe selection and is explained through the Contextual Property Inspector and established visual feedback.

Trajectories, world-space keyframe nodes, frustums, guides, collaborator markers, Gizmo handles, and Preview Stage axes remain inside the current game scene or Abstract Stage Preview and use the same preview camera. World anchors retain depth and perspective, while Stable World Overlay Scale keeps node artwork and independent hit targets usable at supported distances and density profiles. Local selection uses the established Blockbench-inspired blue plus outline or shape reinforcement. Hovering a world node does not enlarge it, add glow, animate it, or reveal inline controls. Ordinary overlays obey scene depth; only a locally selected hidden node or trajectory portion may retain an Occluded Selection Trace so terrain cannot erase the user's active target completely.

If the recorded dimension or safe live rendering is unavailable, the viewport enters Abstract Stage Preview with an explicit reason and preserves the stored stage, grid, axes, trajectories, nodes, and lens visualization. It never silently evaluates against the participant's current position. Immersive Preview remains an explicit local action: entry captures the Camera Restoration Snapshot, and normal exit, Escape, editor close, disconnection, world change, focus loss, dimension failure, or render failure restores or safely degrades the prior client camera and input state. The viewport state transition remains visible until restoration is complete.

Viewport observation, display-layer toggles, fallback presentation, and toolbar overflow are local workspace behavior. They do not edit project content, create revisions, checkpoints, publication, runtime instances, collaboration operations, or personal Undo/Redo entries. The toolbar and frame derive from available relative bounds and preserve the Minimum Usable Region rather than using Minecraft's original absolute screen coordinates or exaggerated global scaling.
