# Establish a bottom editor status bar with a compact workspace entry

Status-detail compression and icon-only fallback follow the Responsive Degradation Order in ADR-0205; the persistent status entry remains reachable even when its full detail surface is not continuously expanded.

The rewritten Camera Animation Editor uses a responsive bottom Editor Status Bar as the detailed status surface. For an Active Project Tab, its compact regions present, from left to right where space permits, connection and editability, accepted revision and persistence state, permission and collaboration presence, active command-event locks, runtime diagnostics, and the current UI Client Player's published-animation enable state. While the Project Browser Tool Tab is active, the same bar switches to catalog connection, query, and failure state and hides stale project-specific revision, persistence, lock, collaborator, and runtime summaries. The top Project Workspace Bar keeps only a concise Workspace Bar Status Entry and the Project Tab Draft Dot; it does not display the internal project revision as ordinary tab content.

When several conditions coexist, Status Priority State determines the primary summary: connection failure or disconnection, then action-required conflict or permission blockage, then synchronization or persistence work, then runtime diagnostics or collaborator activity, with connected-and-ready as the quiet baseline. Every summary has a semantic icon, concise text, and non-color cue. Clicking a revision or persistence item opens read-only revision or persistence details; clicking a lock item opens the bounded holder and affected-object list; clicking the permission item explains the current Owner or Editor scope; clicking the diagnostic badge opens the existing Runtime Diagnostic Panel; and clicking the enabled-animation item opens its local read-only runtime state. None of these routes mutates content, changes the playhead, changes playback, acquires a lock, or enters Undo/Redo.

During a Transient Connection Interruption, reconnecting and Reconnect Revalidation occupy the highest connection-state priority. The status bar identifies the Reconnecting Read-Only State, retained drafts, lost or uncertain leases, and the valid cancel or detail actions without implying that collaborative edits remain available.

When Reconnect Revalidation confirms permission revocation, the status bar changes to the action-required Permission-Revoked Inspection State. It identifies the last authorized view as frozen and potentially stale, shows that the tab has left the Editing Session and no longer receives updates, and exposes only valid draft-material, detail, recheck, or close actions.

The Status Detail Surface is local and bounded. It may remain inline at comfortable widths, become a drawer or popover at narrower widths, and collapse to icon badges before it reduces the Minimum Usable Region of the Live World Viewport or Timeline Panel. It does not retain full network logs, chat, unbounded history, raw command output, private drafts, credentials, or server-owned files. Session notifications, collaborator presence, lock leases, pending operations, and runtime diagnostics follow their existing connected-session lifecycles and are released on connection, world, server, or project-session exit; the status UI itself is not project content, a checkpoint, a Project Workspace Snapshot, or a device preference.

Operation results use the dual feedback contract in ADR-0204: the Editor Status Bar remains the persistent, queryable state surface, while a short-lived Transient Status Notice draws attention to a meaningful result without becoming modal. The notice is non-blocking, opens the relevant Status Detail Surface when selected, and follows bounded Status Notice Coalescing. Field validation, overwrite confirmation, permission confirmation, and other blocking decisions remain on their dedicated surfaces rather than being converted into notices.
