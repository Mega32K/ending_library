# Join collaborative preview through server validation

Joining an existing Collaborative Preview is an explicit player action from the current active Project Tab. It does not require approval, invitation, or a response from the Preview Leader. The server accepts an `Explicit Collaborative Preview Join` only after validating the player's current Project Owner or Project Editor permission, project lifecycle and format, active-tab and editing-session identity, participant capacity, and the current preview-session generation.

On acceptance, the server sends the joining participant the current Preview Revision Snapshot, Preview Stage, logical playhead, playback state, preview range, session generation, and a bounded time reference under `Preview Logical Time Alignment`. If the shared preview is playing, the client begins at the current projected logical time rather than slowly catching up from a stale packet; if it is paused, the client restores the exact authoritative paused time. Small local drift may be corrected without sending edit or shared-control operations. The client captures its local preview playhead, work range, viewport observation, and other valid local preview state before applying the shared state. The participant then follows the existing collaborative-preview control and read-only contracts; joining never changes the gameplay camera, creates a runtime instance, mutates the Project Document, or adds personal Undo/Redo history.

An invalid permission, inactive or stale Project Tab, unsupported format, ended preview, full participant budget, or stale session generation rejects the complete join without partial admission. The client keeps its local preview unchanged and shows a bounded localized reason with a valid manual recovery action. Repeated join clicks are single-flight and never create an unbounded request queue. A participant who leaves later receives Preview Restoration, and a leader departure ends the whole preview under the non-transferable leadership rule.
