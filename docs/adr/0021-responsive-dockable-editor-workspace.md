# Build the editor as a responsive dockable workspace shell

The rewritten Camera Animation Editor uses a Workspace Shell rather than the legacy fixed-coordinate screen. Its primary regions are a top command surface, a default Left Animation Navigation Stack containing the Animation Resource Browser above the Timeline Track Tree Surface, a central Embedded Preview Viewport with Live World Viewport or Abstract Stage Preview content, a bottom Timeline Panel and curve editor, a right Contextual Property Inspector, and a bottom status surface. The central viewport and bottom timeline/curve editor are Core Editor Regions; auxiliary panels can be hidden or moved without removing the complete editing path. The top command surface explicitly includes File and Settings menus in addition to project identity, revision/synchronization status, Undo/Redo, and playback controls.

Regions are arranged with relative weights, minimum and maximum proportions, explicit Dock Zones, dockable panels, Panel Tab Groups, bounded Floating Editor Panels, draggable splitters, and focus-aware input routing. Minecraft's active GUI Scale supplies the outer logical bounds, while the editor applies one of the bounded Compact, Standard, or Comfortable density profiles inside them. A narrow window collapses low-priority panels into drawers or tabs and preserves the viewport/timeline editing path instead of shrinking every component until it overlaps. Typography, spacing, hit targets, node sizes, and toolbar density use bounded scaling. The implementation must derive layout from available content bounds and insets, not Minecraft's original absolute screen coordinates or a second unrestricted scale; all overflow and focus transitions are explicit and testable.

The File Menu owns project/document lifecycle and import/export/recovery commands. The View Menu owns current-client display layers, timeline presentation, panel visibility, workspace presets, and focus-to-content actions. The Settings Menu owns editor-local preferences and reset actions, with simple values available from the menu and complex values opened in the responsive Settings Panel. Neither menu may silently mutate animation content; content changes remain visible Edit Operations with revision and Undo/Redo semantics. Panel focus is part of the UI interaction model, while animation selection and editor workspace snapshots remain separate state.
