# Store animation projects at world scope

Camera-animation projects belong to the server world and remain available independently of the player who created or edited them. Player capabilities continue to represent runtime camera state, while the editor works against world-owned project documents and editing sessions; this avoids coupling durable authoring data to player lifecycle or capability synchronization. Project authorization intentionally uses only two roles: one owner controls project lifecycle and editor membership, while editors can open and modify the project. Players who hold neither role cannot enter that project editing session. Removing the permission of an editor who currently holds a Command Event Personal Edit Lock follows the owner-confirmed Destructive Project Lock Drain rather than silently leaving an unauthorized lease or discarding a draft without warning.
