# Revalidate stale Easing conversion previews semantically

An Easing-to-Bézier confirmation identifies the project revision and complete logical conversion footprint observed when its preview was generated. If later accepted operations are disjoint from that footprint, such as edits on unrelated tracks or unrelated project metadata, the server may semantically rebase the request and authoritatively recompute it against the current revision. If an affected source node's time, value, Easing, existence, ordering, interval adjacency, or relevant track structure changed, the server rejects the complete request without creating project content, a collaboration revision, or personal Undo/Redo history. The editor keeps the conversion window open, displays the changed source intervals, loads current authoritative data, and generates a new preview that requires a new explicit confirmation. It never exposes a force-apply-old-preview action.
