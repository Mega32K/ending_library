# Provide independent local preview and explicit collaborative preview

Every editor previews independently by default. Local play, pause, seek, scrubbing, work range, and viewport changes remain private workspace state, while other participants may be represented only as non-controlling presence indicators such as faint remote playheads.

The default local preview is rendered in an Embedded Preview Viewport with a client-owned preview camera. Joining or starting a Collaborative Preview synchronizes the selected revision and playback state only for participants who explicitly perform an `Explicit Collaborative Preview Join`; it never forces another participant to switch their gameplay camera or enter Immersive Preview.

A participant may explicitly start or join a collaborative preview. Each project has at most one active Collaborative Preview; concurrent starts are serialized so one request creates the session and the other requests receive a bounded already-active result rather than creating parallel or queued shared previews. A start conflict is reported non-blockingly and leaves the caller's local preview untouched; joining requires a separate explicit action. Joining an existing preview does not require approval from its Preview Leader: the server validates the joining active tab's Owner or Editor permission, project lifecycle and format, participant capacity, and current preview session before accepting the `Explicit Collaborative Preview Join`. Before applying shared state, the client captures a bounded `Local Preview Snapshot` containing its valid local animation, playhead, playing or paused state, loop state, work range, viewport observation, timeline presentation, selection, and panel navigation. An accepted join receives the current Preview Revision Snapshot, Preview Stage, playhead, playback state, and preview range. A non-leader joined editor enters `Collaborative Preview Follower State` only while its Project Tab is active: shared play, pause, seek, work-range, and revision-switch controls are read-only and identify the current leader, while local viewport observation, selection, property inspection, and otherwise authorized project editing remain available. Switching to another Project Tab leaves the preview and restores local state rather than retaining a hidden background follower. Those local edits do not alter the immutable active preview revision. Its temporary leader synchronizes the selected project revision, playhead, playback state, and preview range for joined editors. Any participant may leave and restore its valid Local Preview Snapshot before joining. If the Preview Leader voluntarily leaves, disconnects, loses permission, or reaches a connection or project-session lifecycle exit, the server applies `Collaborative Preview Termination` rather than transferring control to another participant. Shared playback and control end, bounded preview resources are released, and every remaining participant receives Preview Restoration. Preview traffic never targets ordinary players outside the editing session; applying a published animation to gameplay remains a separate server runtime action.
