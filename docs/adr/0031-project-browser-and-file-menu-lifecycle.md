# Use the project browser as the editor entry and File as the lifecycle menu

Opening the Camera Animation Editor without a requested project first presents a Project Browser backed by the server-world Project Catalog. It exposes project name, owner, revision, recent edit time, editor count, archive state, and the current player's recent-open information, with search, sorting, and filters for owned, editable, recent, and archived projects. Opening a current-format project creates or activates its Project Tab and joins its Editing Session. Opening a supported older project first enters the explicit Project Migration Prompt, while a newer unsupported project may enter only its protected read-only compatibility flow; neither path silently creates an editable session. A read-only opening uses a Read-Only Inspection Tab: it has no detailed collaborator presence or project-edit subscriptions.

The Project Browser is non-destructive when another project is open: it uses the single temporary Project Browser Tool Tab and does not close any Project Tab. Activating the tool tab leaves the previously active project's Editing Session and presence after applying the normal pending-operation and retained-draft safeguards; returning to that project rejoins its current authoritative revision and restores its saved workspace state. The File Menu centralizes create, browse/open, recent projects, close tab, import legacy JSON, export legacy or project format, duplicate, archive, restore, recovery, history inspection, and explicit checkpoint commands. History inspection opens the read-only Project History and Recovery Panel for both Owner and Editor without changing project or runtime state; any restore launched from it follows the existing checkpoint-restore safeguards. All content-changing lifecycle actions remain server-authorized operations with visible confirmation and revision behavior. Save/checkpoint, export, publication, and history inspection remain Lock-Neutral Project Operations over accepted revisions; deletion, archive, checkpoint restoration, and replacement import require a successful Destructive Project Preflight before any affected command-event leases or drafts are drained.

After a successful archive, every open tab for the affected project changes to Archived Inspection State in place and shows the last authorized content without retaining a live session. A later restore changes only the server catalog lifecycle; players must explicitly open or rejoin the project to edit it again. After successful deletion, every open tab changes to Deleted Project Notice and exposes no project content. Failed lifecycle operations leave existing tabs and their valid local state unchanged.
