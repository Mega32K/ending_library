# Confirm keyframe overwrite on insertion

The Overwrite Confirmation is a Blocking Transaction Surface under ADR-0203. It owns input, defaults focus to cancellation, and cannot be silently stacked with another blocking prompt.

The confirmation applies uniformly to Keyframe Creation and Insertion actions, Auto Key, and any other menu or inspector route that proposes the same-track, same-lane, same-time write.

Keyframe insertion and Auto Key use an explicit Overwrite Confirmation when the requested write targets an existing keyframe in the same `ModifierType` scalar track and Additive Lane at the same canonical time. The confirmation is required for timeline insertion, inspector insertion, Auto Key, and equivalent batch insertion paths; the editor must not silently merge or update the existing keyframe. A single multi-target gesture displays one grouped confirmation dialog listing every affected target and its old-versus-incoming value; it does not open one dialog per target. The popup identifies the animation, scalar track, Additive Lane, and canonical time, shows the existing value beside the incoming value, focuses `Cancel` by default, and does not offer a permanent “do not ask again” setting. Confirming replaces the existing authored value while preserving the target keyframe identity and submits the value change, any linked-channel changes, and any duration extension as one ordinary edit transaction and one Undo/Redo item. Cancelling closes the prompt without changing project content, revision history, or personal Undo/Redo history. The server revalidates the target keyframe identity and value at confirmation time; if another participant changed, removed, or retimed the target after the popup opened, the overwrite is rejected as a conflict rather than force-applied. Different tracks and Additive Lanes may still contain keys at the same time.
